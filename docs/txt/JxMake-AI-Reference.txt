NOTATION TEMPLATE  (used uniformly for every grammar rule and every built-in function below)

GRAMMAR RULES: kept as exact EBNF (see PART 1 header for the EBNF conventions themselves, copied
verbatim from the grammar file). Every [WS-*] whitespace-convention tag is preserved exactly where
the source placed it. Explanatory (* ... *) prose comments are compacted to short trailing "--"
annotations or dropped when purely restating the rule name.

BUILT-IN / user-facing FUNCTION ENTRIES use this one-line-signature + note-lines template:

    $func_name(param:type, opt:type=default, [opt2:type=default]) -> ret_type
        # behavior; throws/errors; enum values; JSON schema (compact) or pointer to full example

  - Required parameter:      name:type
  - Optional parameter:      [name:type=default]   (default value always shown; 'default: none'
                              if the source states no default / not specified)
  - No parentheses content at all => function takes no arguments: $func_name()
  - Return type shown as "-> type" immediately after the parameter list; omitted entirely (no "->")
    for functions that are statements only (no useful return value, source shows no <output> column)
  - TYPE TOKENS:
        str        plain string value (may be a multi-member set; most ops apply per-member)
        int        signed integer
        bool       0 or 1 (source functions that accept 'true'/'false' words: noted per-entry)
        path       filesystem path string
        set        multi-member value where member count/order is semantically significant
        handle:X   opaque handle of kind X (map, stack, bse, fwc, ...) from an $X_new()-style call
        json       JSON-formatted string parameter/return (schema given inline, compact)
        edata      opaque "encoded representation data" string (map/stack serialization)
        term       any term (see grammar PART 1 Sec 3.1)
        any        unconstrained
  - "# notes" lines carry: default values, valid enum/const values, throw/error conditions,
    flatten-before-use argument notes, bool-word-coercion notes, and (for JSON/INI parameters)
    the compact field schema. Full worked JSON example blocks are NOT reproduced; instead:
        "full example: docs/txt/en_US/99-Appendix-X_Built-In-Function-Parameters.txt § <section>"
  - Functions are grouped/ordered exactly as in source 07-Built-In-Functions.txt so this file
    stays easy to diff against source mentally.

PART 1 -- FORMAL GRAMMAR  (from JxMake-Grammar.txt; ground truth for parsing)
====================================================================================================

EBNF CONVENTIONS: rule ::= definition | A B (concat) | A|B (alt) | [A] (0-1) | {A} (0+ Kleene) |
A+ (1+) | (A) (group) | 'literal' | <TOKEN> (terminal class, prose-defined) | (* comment *).
Lowercase = non-terminal. ALL-CAPS in <> = terminal class. SUGAR rules expand to a canonical core
form and are annotated "SUGAR:"; may become first-class in future versions (grouped in Sec 9).

WHITESPACE TAGS (attached per-production): [WS-SEP] >=1 whitespace required between tokens (GLOBAL
DEFAULT when untagged) | [WS-OPT] optional | [WS-NONE] forbidden (tokens must be adjacent) |
[WS-SIG] whitespace is structurally significant (e.g. inside {{ }} / { }) | [WS-INNER] whitespace
inside quoted strings is literal (part of the string value).

INDEXING: JxMake indices start from 1. Zero = invalid/not-found index.

SEC 1 -- LEXICAL BASICS
----------------------------------------------------------------------------------------------------

    encoding        ::= (* UTF-8, case-sensitive *)

    physical-line   ::= <LINE-CONTENT> [ '#' <comment-text> ] <NEWLINE>
    logical-line    ::= physical-line | physical-line '\' <NEWLINE> logical-line
                        -- trailing '\' joins next physical line; an EMPTY line terminates an
                           in-progress '\' continuation (NOT transparent inside the chain)
    statement-sep   ::= <NEWLINE> | ';'
                        -- ';' is a GLOBAL separator: forces a new logical line anywhere, same as a
                           physical newline, incl. after the RHS of a one-liner if. Never "consumed"
                           by a surrounding construct.
    empty-line      ::= <NEWLINE>   -- ignored

    line-comment    ::= '#' <comment-text>              -- to end of physical line
    block-comment   ::= '(*' <any-text> '*)'             -- multiline

    ident           ::= <LETTER-OR-UNDERSCORE> { <LETTER-DIGIT-UNDERSCORE-DOT-SLASH-...> }
                        -- must not start with digit; '.' and '/' allowed in some contexts (e.g.
                           target names/paths); exact charset is context-dependent
    special-ident   ::= '__' <IDENT-BODY> '__'           -- special-variable shortcut name

    raw-string       ::= '`' <raw-chars> '`'                                        [WS-INNER]
                         -- NO evaluation/escapes at all
    single-string    ::= "'" <sq-chars> "'"                                         [WS-INNER]
                         -- only '\\'->\ and "\'"->' recognised; all other \X stored literally as \X
    double-string    ::= '"' <dq-chars> '"'                                         [WS-INNER]
                         -- full var+escape eval; function calls inside are NOT evaluated (plain
                            text); ."..." and :"..." force immediate single-member evaluation
    multiline-string ::= '[["' <NEWLINE> <ml-chars> <NEWLINE> '"]]'
                         [WS-SIG: all inner whitespace preserved verbatim]
                         -- same eval rules as double-string; func calls NOT evaluated; '[["' must be
                            alone on its line; '"]]' must be alone on its line (nothing before/after);
                            not all statement contexts accept multiline strings
    integer-lit      ::= ['-'] <DIGITS> | '0x' <HEX-DIGITS> | '0o' <OCT-DIGITS>
    bare-word        ::= <IDENT>   -- unquoted non-keyword token used as value/filename/varname

----------------------------------------------------------------------------------------------------
SEC 2 -- COMPILER DIRECTIVES (::: prefix)                                    [WS-SEP throughout]
----------------------------------------------------------------------------------------------------

    pragma-stmt    ::= ':::pragma' 'jxmake_compile_minimum_version' version-spec
                     | ':::pragma' 'jxmake_compile_maximum_version' version-spec
    version-spec   ::= <DIGITS> '.' <DIGITS> '.' <DIGITS>       [WS-NONE within version-spec]
                        -- e.g. 1.0.1; compile error if running JxMake version violates the pragma

    include-stmt   ::= include-kw include-target
    include-kw     ::= ':::include' | ':::sinclude' (safe: no error if missing)
                     | ':::include_once' | ':::sinclude_once' (safe + once)
    include-target ::= <LIBRARY-NAME>          -- bare name, resolved as library
                     | single-string           -- file path; plain text only, NO variable expansion
    -- 'once' semantics: guard is GLOBAL for the whole compile run (main file + all recursive
       includes); tracked by RESOLVED ABSOLUTE PATH (two arg strings resolving to same file = one
       entry); ':::include_once' and ':::include' track INDEPENDENTLY (loading via one does not
       suppress the other's first invocation); skip message printed to stdout when suppressed.
    -- Library search path order (POSIX): $HOME/0-JxMake/lib, $HOME/.jxmake/0-JxMake/lib,
       $HOME/.share/0-JxMake/lib, $HOME/.share/jxmake/0-JxMake/lib, /usr/local/share/jxmake/0-JxMake/lib,
       /usr/share/jxmake/0-JxMake/lib, /var/lib/jxmake/0-JxMake/lib, /opt/jxmake/0-JxMake/lib,
       <dir containing class/jar>/0-JxMake/lib, then files embedded in the JAR (last resort).
       (Windows): %HOMEDRIVE%%HOMEPATH%\0-JxMake\lib, ...\AppData\0-JxMake\lib, ...\AppData\Local\...,
       ...\AppData\Roaming\..., ...\Local Settings\ApplicationData\0-JxMake\lib, ...\.jxmake\0-JxMake\lib,
       %APPDATA%\0-JxMake\lib, %LOCALAPPDATA%\0-JxMake\lib, <dir containing class/jar>\0-JxMake\lib,
       then JAR-embedded (last resort).
    -- If a precompiled '*.jxm.bin' exists and is newer than its '*.jxm' source, the precompiled file
       loads instead (except JAR-embedded libraries: source only, always). 'ArduinoBoardsTxt_Dec.RULES.txt'
       is searched in the same directory list (no 'lib' suffix); falls back to JAR-embedded default rules.

SEC 3 -- TERMS, VALUES, EXPRESSIONS
----------------------------------------------------------------------------------------------------

3.1  A "term" is any unit producing a value (1+ set members):
    term ::= var-eval | auto-var-eval | func-call | double-string | multiline-string | single-string
           | raw-string | combining-string (."..." SUGAR, Sec 9.1) | flattening-string (:"..." SUGAR, Sec 9.2)
           | special-ident | bare-word | integer-lit | set-creation-op ({ } SUGAR, Sec 9.5)
           | stack-shortcut ({{ }} SUGAR, Sec 9.4) | partn-shortcut (<n> SUGAR, Sec 9.3)
           | path-shortcut (~/^/- SUGAR, Sec 9.6) | ref-var-eval (${^x} indirect eval)

3.2  var-eval      ::= '${' var-name '}'                                          [WS-NONE inside braces]
                     | '${' var-name '/' regexp-str '/' [ replace-str ] '/' '}'   -- in-var regex (Sec 6)
     auto-var-eval ::= '$[' auto-var-name ']'                                     [WS-NONE inside brackets]
                     | '$[' auto-var-name '/' regexp-str '/' [ replace-str ] '/' ']'
     -- ALL $[...] auto-vars are ALWAYS DIRECT regardless of '=' vs ':=' (physically impossible to
        defer: cmdecho/cmdstreaming reflect current on/off state; preq* are fully resolved before
        the target body runs; excode/stderr/stdout are output of the preceding '@' block; lserr is
        cleared after each read). '=' on a $[...] var is silently treated as ':='.
     ref-var-eval  ::= '${' '^' var-name '}'      [WS-NONE, ^ adjacent to var-name]
                     -- SUGAR: value of the variable NAMED BY var-name (indirect/reference deref)
     var-name      ::= ident | special-ident
     auto-var-name ::= 'cmdecho' | 'cmdstreaming' | 'lserr' | 'jxmakefile' | 'function' | 'cmdtargets'
                     | 'usn' | 'target' | 'preq^' | 'preq*' | 'preq?' | 'preq1' | 'preq2' | 'preqN'
                     (N = any positive int) | 'preq:' <IDENT> (${V}-th prereq; V = plain var name)
                     | 'preq+' | 'preq%' | 'preq~' | 'excode' | 'stderr' | 'stdout'

3.3  dq-escape (double-quoted strings only) ::=
       '\t'(0x09) | '\v'(0x0B) | '\r'(0x0D) | '\n'(0x0A) | '\f'(0x0C) | '\b'(0x08) | '\''' | '\"'
     | '\\' | '\$' | '\~' | '\`' | '\-' | '\+' | '\?'
     | '\o' 3-OCTAL-DIGITS (000-377) | '\d' 3-DECIMAL-DIGITS (000-255) | '\x' 2-HEX (00-FF)
     | '\u' 4-HEX (U+NNNN) | '\U' 6-HEX (U+NNNNNN)
     -- all other \X: backslash stripped, X stored (may raise error for \o/\d/\x/\u/\U on bad digits)
     -- single-quoted: only \' and \\ recognised, else stored literally incl. backslash
     -- raw-quoted: no escapes at all, verbatim

3.4  func-call      ::= [ error-suppress ] '$' func-name '(' [ arg-list ] ')'
                        [WS-NONE between '$'/func-name and func-name/'(']  [WS-OPT around '(' first-arg, last-arg ')']
     error-suppress ::= '-'   -- suppresses runtime error, message goes to stderr
     func-name      ::= ident  -- built-ins start with '$'; user-defined via 'function' keyword
     arg-list       ::= arg { ',' arg }                          [WS-OPT around commas; WS-SEP within each arg]
     arg            ::= term | '?'
                        -- bare unquoted '?' passes the default for an optional param (distinct from
                           the 1-char string '?'); e.g. $call(func,'a',?,?,'e'). '???' or other
                           repetition = plain bare-word string, NOT multiple defaults.
     -- DISAMBIGUATION: '-' before '$func_name(' = error-suppress prefix, NOT the path-shortcut '-'
        (Sec 9.6), which applies only immediately before '${' or '$['.

----------------------------------------------------------------------------------------------------
SEC 4 -- VARIABLE ASSIGNMENT STATEMENTS                    [WS-SEP between all tokens unless noted]
----------------------------------------------------------------------------------------------------

4.1  assignment-stmt        ::= direct-assignment-stmt | indirect-assignment-stmt
     direct-assignment-stmt ::= [ modifier ] var-name assign-op term+
     modifier   ::= 'local' | 'const' | 'local' 'const'
                    -- local: scopes to current function/target; const: assign-once, ':=' only;
                       combinable as 'local const'
     assign-op  ::= '='   (lazy: eval on read)
                  | ':='  (direct: eval on assign)
                  | '+='  (concat, lazy)          | ':+=' or '+:=' (concat, direct; equivalent alternates)
                  | '?='  (if-not-set, lazy)      | ':?=' or '?:=' (if-not-set, direct; equivalent alternates)
     indirect-assignment-stmt ::= '^' var-name assign-op term+     [WS-NONE '^'-var-name; WS-SEP elsewhere]
                        -- assigns to the variable NAMED BY var-name's current value (RefA=VOrg; ^RefA:=20
                           sets VOrg, not RefA). 'modifier' prefix NOT supported. 'unset ^var' = SYNTAX ERROR.
     -- GENERAL: 'const' only supports ':='. CLI args auto-become constant variables. Not all
        statements support lazy ('=') assignment. $[...] auto-vars always behave direct even with '='.
        Lazy assignment of a function-call RESULT is not supported. Non-existent vars evaluate to
        empty string / 0 by convention.

4.2  unset-stmt     ::= 'unset' var-name   -- only plain names; 'unset ^var' = SYNTAX ERROR (read the
                        ref into a plain var first, then unset that name)

4.3  deprecate-stmt ::= 'deprecate' var-name [ 'by' var-name ]
                        -- marks deprecated, optional replacement name; if a local var of the same
                           name exists in current scope, the LOCAL one is marked; params can't be marked

5.2  Writable:

SEC 8 -- USER-DEFINED FUNCTIONS AND SHELL EXECUTION
----------------------------------------------------------------------------------------------------

8.1  func-def   ::= 'function' func-name '(' [ param-list ] ')' func-modifiers { statement } 'endfunction'
     param-list ::= param-name { ',' param-name }
     param-name ::= ident | '?' ident     -- '?'-prefixed = optional; ALL params after the first
                     optional must also be optional
     func-modifiers ::= [ 'supersede' ] [ 'deprecated' [ 'by' func-name ] ]
     -- 'supersede' replaces a prior same-named function; inside it, $call(__origin__,...) invokes
        the previous definition in the chain; a superseding function MAY have different params.
        Call with bare unquoted '?' to use an optional arg's default: $call(f,'a1','a2',?,?,'a5').
        Local vars declared in a function outrank global vars and same-named parameters.
        Caller's params/locals are IMPLICITLY INHERITED by the callee as extra by-value args unless
        the callee declares same-named params. 'return' with no value returns empty string.

8.2  exec-func-def ::= 'function' func-name '(' [ param-list ] ')' func-modifiers { exec-stmt | statement } 'endfunction'
     exec-stmt ::= '@' <cmd>        -- execute OS command
                | '-@' <cmd>        -- execute, suppress runtime error (message to stderr unless silent mode)
                | '+@' <cmd>        -- execute + print command first (affected by $cmd_echo_off/on)
                | '-+@' <cmd>       -- execute + print + suppress error
                | '?@' <cmd>        -- print command only, do NOT execute (affected by $cmd_echo_off/on)
     -- Text after '@' to end-of-line or '#' is the command. Consecutive '@' commands buffer and run
        as a group (outputs concatenated); accessing $[excode]/$[stderr]/$[stdout] flushes the buffer.
        Function-call results cannot be passed as '@' argument text directly -- precompute into a temp var.
        An $exec function CANNOT call any other user function via $call/$exec anywhere in its body --
        runtime error: "RUNTIME ERROR: a user-defined function called using '$exec()' is not allowed
        to call other user-defined functions". Non-call statements (assignment/conditional/loop/etc.)
        ARE permitted inside $exec bodies. '$call'/'$exec' cannot be prefixed with '-'.
        Non-zero exit code stops the command sequence at that point but is usually not itself a
        runtime error -- always check $[excode]. Streaming disabled by default (stderr/stdout captured
        to vars, not printed); enable via $cmd_streaming_on (then only $[excode] is populated;
        stderr/stdout print directly as commands execute instead).

8.3  env-modifier ::= '@clrenv' | '@delenv' <ENV-VAR-NAME> | '@setenv' <ENV-VAR-NAME> term+
                    | '@addenv' <ENV-VAR-NAME> term+ | '@sstdin' term+ | '@jxmake' arg-list
     -- affects only the immediately following command group; must be reapplied per non-consecutive
        group. '@jxmake' spawns a NEW PROCESS (unlike 'jxmake'/'+jxmake' target keywords, which reuse
        the thread/thread-pool); of the original CLI args, only --dct/--lct auto-pass to '@jxmake'
        (overridable). '@sstdin' sends its value to only the NEXT one command (call repeatedly to
        pipe to multiple); may not work if '@' streaming is enabled (may hang/error).

SEC 9 -- SHORTCUT / SUGAR OPERATORS  (currently sugar; may become first-class in future)
----------------------------------------------------------------------------------------------------

9.1  combining-string  ::= '.' double-string    [WS-NONE '.'-'"']
     -- SUGAR: "..." whose set members are COMBINED (no separator) to ONE member. CORRECTION (tested
        against actual runtime behavior; the grammar file's own prose claims this is "ALWAYS LAZY,
        regardless of '='/':='" -- that claim is FALSE, confirmed by direct testing): the combining
        effect (and its lazy re-evaluate-on-every-read tracking) ONLY takes effect through LAZY ('=')
        evaluation, or when the term is evaluated inline (e.g. as a bare function-call argument, with
        no assignment at all). Under DIRECT (':=') assignment, '.' has NO EFFECT WHATSOEVER: the term
        is evaluated exactly once, exactly as if the '.' prefix were absent (produces the SAME
        multi-member, non-combined result a plain "..." would, frozen at assignment time, no tracking).
        Tested proof (docs/txt/en_US/04-Defining-Variables.txt):
            D='d';E='e';F='f'
            Q  = ."${D}|${E}|${F}"   ; X := ."${D}|${E}|${F}"   ; Y := :"${D}|${E}|${F}"
            echoln ${Q}  # 'd|e|f'   echoln ${X}  # 'd|e|f'   echoln ${Y}  # 'd|e|f'
            D='D';E='E';F='F'
            echoln ${Q}  # 'D|E|F'  <- lazy '=', combines AND tracks
            echoln ${X}  # 'd|e|f'  <- ':=' defeats the '.' entirely; frozen, same as plain "..." would be
            echoln ${Y}  # 'd|e|f'  <- ':=' + flattening: frozen (flattening is always-direct anyway)
        Tested proof (docs/txt/en_US/02-Defining-Strings.txt), member counts, all three CONFIRMED CORRECT:
            Val:=10; Val:="There are ${Val} large rocks."  ; $part_count(${Val}) -> 3 (plain, 3 members)
            Val:=10; Val:=."There are ${Val} large rocks." ; $part_count(${Val}) -> 3 (SAME as plain --
                                                               ':=' defeated the '.', no combining occurred)
            Val:=10; Val:=:"There are ${Val} large rocks." ; $part_count(${Val}) -> 1 (flattening: always
                                                               collapses to 1 member regardless of '='/':=')
        PRACTICAL RULE: use ."..." only (a) directly as a bare term/function argument (to collapse a
        multi-member "..." into one argument and avoid the "non-flattened string" compile error -- see
        $printf example below), or (b) assigned via lazy '=' when you want live tracking. Assigning a
        ."..." term via ':=' is USELESS -- it behaves identically to a plain "..." assigned via ':='
        (same member count, same frozen-at-assignment-time value). If you want a one-time frozen single
        member, use the flattening operator :"..." instead (works correctly under both '=' and ':=').
        Example showing the correct usage as a function argument (why the operator exists at all):
            D=10; S=20; X=A; Z=B
            $printf( ."#%${D}d '%${S}s'\n", 123, ."${X}${Z}" )   # works
            #$printf(  "#%${D}d '%${S}s'\n", 123,  "${X}${Z}" )  # compile error (multi-member arg)

9.2  flattening-string ::= ':' double-string    [WS-NONE ':'-'"']
     -- SUGAR: "..." whose set members are FLATTENED (no separator) to ONE member. ALWAYS DIRECT
        (evaluated once at assignment, frozen). D = :"${A} ${B}" freezes at assign time.

9.3  partn-shortcut ::= partn-operand '<' index-spec '>'      [WS-NONE operand-'<'; WS-OPT index tokens]
     partn-operand  ::= '${' var-name '}' | '$[' auto-var-name ']'
     index-spec ::= index-val | index-val ',' offset-val | beg-val ':' end-val   (each val: integer-lit | '${'var-name'}')
     SUGAR: ${V}<N> -> $partn(${V},N) | ${V}<VN> -> $partn(${V},${VN}) | ${V}<N,O> -> $partn(${V},N,O)
          | ${V}<VN,VO> -> $partn(${V},${VN},${VO}) | ${V}<B:E> -> $partnm(${V},B,E)
          | ${V}<VB:VE> -> $partnm(${V},${VB},${VE})   (same forms for $[V])
     -- expands to a DIRECT function call (no temp vars) -> subject to all func-call placement rules;
        NOT evaluated inside plain "..."; IS evaluated inside ."..." or :"...".

9.4  stack-shortcut ::= '{{' WS term { ',' WS term } WS '}}'   [WS-SIG: whitespace between {{ }} MANDATORY]
     SUGAR: {{ v1, v2, v3 }} -> $stack(v1, v2, v3)
     -- no temp vars; subject to func-call placement rules; NOT evaluated inside plain "...", IS
        evaluated inside ."..." / :"...". Inside strings, '{{'/'}}' are literal text.

9.5  set-creation-op ::= '{' WS term+ WS '}'   [WS-SIG mandatory whitespace; WS-SEP between terms;
                          commas are NOT separators here]
     SUGAR: { v1 v2 v3 } -> (tmp := v1 v2 v3) and then ${tmp}
     -- CRITICAL: commas inside { } are LITERAL BARE-WORD MEMBERS: { A, B, C } = 5 members (A , B , C),
        not 3. Use whitespace only. Contrast {{ }} where commas ARE separators: {A B C}=3 members
        (set-creation); {{A,B,C}}=$stack(A,B,C)=3 members (stack shortcut).
        Valid ONLY as operand of: return stmt, extradep stmt, prereq names in target-def, input set of
        foreach, args of built-in/user function calls. Elsewhere: may misbehave or fail to compile.
        Inside plain "...", '{'/'}' are literal text.

9.6  path-shortcut ::= '~' var-or-auto-var | '^' var-or-auto-var | '-' var-or-auto-var   [WS-NONE op-operand]
     var-or-auto-var ::= '${' var-name '}' | '$[' auto-var-name ']'
     SUGAR (each uses auto-generated temp vars):
       ~${V} -> $path_ndsep($cat_path($cwd(),${V}))     ~$[V] -> $path_ndsep($cat_path($cwd(),$[V]))
       ^${V} -> $path_ndsep($cat_path($ptd(),${V}))     ^$[V] -> $path_ndsep($cat_path($ptd(),$[V]))
       -${V} -> $path_ndsep($rel_path(${V}))            -$[V] -> $path_ndsep($rel_path($[V]))
     -- Because temp vars are reused elsewhere, ALWAYS store results with ':=' (never lazy '=').
        UNLIKE most func calls, these ARE evaluated inside double-quoted strings.
     -- DISAMBIGUATION: '-' here is the path-to-relative shortcut, NOT negation, and NOT the
        error-suppress '-' before '$func(...)' (Sec 3.4). '~' before ${/$[ is ALWAYS this cwd-relative
        shortcut (never "home directory" as in POSIX shell) -- use $uhd() for the home directory.

9.7  ref-var-eval (read) ::= '${' '^' var-name '}'   [WS-NONE throughout]
     SUGAR (read):  ${^RefVar} -> evaluate the variable NAMED BY RefVar's current value
     (write; = indirect-assignment-stmt, Sec 4.1):  '^' var-name assign-op term+   [WS-NONE '^'-var-name]
     SUGAR (write): ^RefVar := 20 -> lookup name in RefVar (e.g. 'VOrg') then VOrg := 20
     Example: RefA = VOrg ; ^RefA := 20  (assigns VOrg, not RefA) ; ${^RefA} reads VOrg = '20'
     -- Constraints: indirect vars usable only as: read term ${^V}, ${^V}<n> in partn shortcuts,
        foreach iterand; write '^var assign-op term+'. 'modifier' (local/const) NOT valid on write.
        'unset ^var' = SYNTAX ERROR. ${^V} is NOT evaluated inside plain "..." -- use ."${^V}" or
        :"${^V}" as standalone terms instead.

----------------------------------------------------------------------------------------------------
SEC 10 -- STATEMENTS                                        [WS-SEP between all tokens unless noted]
----------------------------------------------------------------------------------------------------

10.1  depload-stmt ::= ( 'depload' | 'sdepload' ) term   -- sdepload = safe (no error if missing)
      -- loads a GNU-Make-format dependency file GLOBALLY; disables auto-detection for targets whose
         deps load this way; relative paths resolve against the dep file's own location.

10.2  target-def ::= 'target' target-name-expr [ ':' prereq-list ] { extradep-stmt } { statement } 'endtarget'
      target-name-expr  ::= target-plain-term { target-plain-term }   -- at most ONE func call allowed
      target-plain-term ::= bare-word | var-eval | single-string | flattening-string | combining-string
                             (."..." VALID for target name)
      prereq-term ::= bare-word | var-eval | single-string | flattening-string
                       -- plain "..." and ."..." are INVALID here ("non-flattened double-quoted
                          string is not allowed here")
      -- FUNCTION-CALL CONSTRAINT (target name AND prereq name): at most ONE func call per name expr;
         when used, no other term may follow it. In prereq position $func(:"...") valid,
         $func(."...") invalid (same error). '$func(...) $func(...)' invalid in both positions
         ("function call cannot be followed by more expression(s)").
         ASYMMETRY SUMMARY: ."..." valid in TARGET name, INVALID in PREREQ name; ."..." as a func
         ARGUMENT is invalid in either position.
      prereq-list ::= prereq-expr { prereq-expr }
      prereq-expr ::= term   -- '%'/'?' are glob wildcards in target names; '%' in prereq names
                       refers back to the captured portion
      extradep-stmt  ::= 'extradep' [ specific-target ':' ] { dep-path }
      specific-target ::= target-name-expr
      dep-path ::= [ '!' ] term   -- '!' prefix includes the path even if non-existent at stmt time
      -- A target with no prereqs is ALWAYS re-executed (unless a same-named file/dir exists). '?'
         matches one char, '%' matches multiple; '%1'-'%9' reference specific captured groups.
         extradep statements must precede all other statements in the target body. A target named
         '.PHONY' (or listing .PHONY as a prereq) always executes.

10.3  run-target-stmt ::= 'jxmake' target-name-expr {target-name-expr} | '+jxmake' target-name-expr {...} | 'jxwait'
      -- 'jxmake' sequential; '+jxmake' parallel (queues target); 'jxwait' waits for queued '+jxmake'
         targets (without it: subsequent 'jxmake' may misbehave, and the program may exit before
         parallel targets finish).

10.4  echo-stmt   ::= 'echo' term+      -- print concatenated, NO trailing newline
      echoln-stmt ::= 'echoln' [ term+ ]  -- print + newline; no args = newline only
      -- both flatten all arguments into one string before printing.

10.5  arith-stmt ::= [ 'local' ] arith-op var-name [ ',' term [ ',' term ] ]
      arith-op ::= 'inc'(dst++) | 'dec'(dst--) | 'add'(v1+v2) | 'sub'(v1-v2) | 'mul'(v1*v2) | 'div'(v1/v2)
                 | 'mod'(v1%v2) | 'abs'(|v1|) | 'neg'(-v1) | 'shl'(v1<<v2) | 'shr'(v1>>v2) | 'min' | 'max'
                 | 'not'(~v1,bitwise) | 'and'(v1&v2) | 'or'(v1|v2) | 'xor'(v1^v2)
      -- all carried out as DIRECT (:=) assignment; all values flattened to one string first; all
         treated as signed ints ('true'/'false' are NOT special words here -- always evaluate to 0).

      eval-stmt ::= [ 'local' ] 'eval' var-name ':=' eval-expr
      eval-expr ::= eval-term+
      eval-term ::= eval-operand | eval-unary-op eval-operand [WS-NONE unary-operand]
                  | eval-binary-op [WS-SEP both sides] | eval-inline-func
      eval-operand   ::= var-eval | integer-lit | '(' eval-expr ')'
      eval-unary-op  ::= '+' | '-' | '@' | '~' | '!'
      eval-binary-op ::= '**' | '*' | '/' | '%' | '+' | '-' | '<<' | '>>' | '<=>'
                        | '<' | '<=' | '>' | '>=' | '==' | '!=' | '&' | '^' | '|' | '&&' | '||' | '?' | ':'
      eval-inline-func ::= inline-fname '[' WS eval-operand { ',' WS eval-operand } WS ']'   [WS-SIG exact format]
      inline-fname ::= 'sgn' | 'min' | 'max'
      -- PRECEDENCE (high->low): + - @ (unary, R-to-L) ; ~ ! (unary, R-to-L) ; ** (L-to-R) ; * / % (L-to-R) ;
         + - (L-to-R) ; << >> (L-to-R) ; <=> (L-to-R) ; < <= > >= (L-to-R) ; == != (L-to-R) ; & (L-to-R) ;
         ^ (L-to-R) ; | (L-to-R) ; && (L-to-R) ; || (L-to-R) ; ?: (R-to-L, ternary).
         Unary ops: NO whitespace to operand. Binary ops: MUST have whitespace. Inline funcs must be
         written exactly `fname[ a , b ]`. '__xxx__' special vars NOT supported in eval (use temp
         locals). Non-inline '$func(...)' calls NOT supported in eval (use temp locals). All numbers
         signed int; 'true'/'false' are not keywords here.

10.6  macro-def   ::= '.macro' macro-name { statement } '.endmacro'
      macro-use   ::= '.' '$' macro-name   [WS-NONE '.'-'$']
      macro-undef ::= '.undefmacro' macro-name
      -- macros take NO parameters (text substitution, like C #define); NOT scoped by conditionals
         (can't have same-named macros conditionally selected); saved into precompiled library files
         only when compiling with '--__compile__'; in cache files all usages stored pre-expanded;
         recommended to use sparingly and undefine after use.

10.7  option-stmt  ::= '.option' 'warning' option-mode [ option-spec ]
      option-mode  ::= 'push' | 'pop' | 'disable' | 'enable'
      option-spec  ::= single-string   -- valid values: 'inv-ref-var' | 'var-not-exist' | 'cnv-integer' | 'cnv-boolean'
      -- 'push' saves current warning state; 'pop' restores the previously pushed state.

10.8  (deprecate-stmt -- see Sec 4.3)

SEC 11 -- FLOW CONTROL                                      [WS-SEP between all tokens unless noted]
----------------------------------------------------------------------------------------------------

11.1  if-stmt ::= if-oneliner | if-block
      if-oneliner   ::= 'if' condition ':' oneliner-stmt
      oneliner-stmt ::= assignment-stmt | indirect-assignment-stmt | arith-stmt | eval-stmt | echo-stmt
                      | echoln-stmt | func-call-stmt | 'return' [term+] | 'break' | 'continue'
                      | run-target-stmt | unset-stmt
      -- ';' forces a new logical line anywhere (Sec 1.2); the one-liner takes exactly the first
         statement after ':' (ends at next newline/';'). Anything after ';' is an independent
         statement on the same physical line, unconditional (does NOT depend on the if):
             if ${A} : echoln 123 ; echo 456   ==   if ${A} : echoln 123 \n echo 456
         NOT permitted as oneliner-stmt: block/compound constructs (if/elif/else/endif, loop blocks,
         func-def, target-def).
      if-block ::= 'if' condition {statement} {'elif' condition {statement}} ['else' {statement}] 'endif'
      condition ::= val '&==' val (string eq) | val '&!=' val (string neq)
                 | val '==' val | val '!=' val | val '<' val | val '<=' val | val '>' val | val '>=' val (int)
                 | val (shortcut: val != 0) | '!' val [WS-NONE] (shortcut: val == 0)
                 | '&' val [WS-NONE] (shortcut: val &!= '') | '!' '&' val [WS-NONE] (shortcut: val &== '')
      val ::= term
      -- condition eval flattens multi-member sets to one string first; 'true'/'false' -> 1/0.
      -- DISAMBIGUATION: 'if __os_windows__' etc. at FILE SCOPE act as compile-time conditionals when
         the condition uses special-var shortcuts (__os_*__, __jxm_ver_*__, ...) -- grammar is
         identical to runtime 'if', distinction is semantic. func-def IS valid inside such file-scope
         if-blocks (enables platform-specific implementations).

11.2  for-stmt     ::= 'for' ['local'] var-name ':=' term 'to' term 'step' term {statement} 'endfor'
                        -- control values evaluated ONCE before the loop starts
      foreach-stmt ::= 'foreach' ['local'] [var-name ','] var-name 'in' term ['skip' term] ['step' term]
                        {statement} 'endforeach'
                        -- optional index-var holds current 1-based index; 'local' applies to BOTH
                           index and value var; subject+control values evaluated ONCE before loop starts
      while-stmt   ::= 'while' condition {statement} 'endwhile'
                        -- condition func calls evaluated ONCE before the loop starts
      do-whilst-stmt ::= 'do' {statement} 'whilst' condition
                        -- condition func calls evaluated EACH iteration
      repeat-until-stmt ::= 'repeat' {statement} 'until' condition
                        -- condition func calls evaluated EACH iteration
      loop-stmt    ::= 'loop' {statement} 'endloop'      -- infinite; exits only via 'break'
      loop-control ::= 'continue' (next iteration) | 'break' (exit loop)
      -- 'true'/'false' -> 1/0 in loop conditions too.

11.3  label-stmt ::= 'label' label-spec ':'
      goto-stmt  ::= ('goto'|'sgoto') label-spec    -- sgoto: no error if label missing
      label-spec ::= ident | single-string   (goto also allows: combined/flattened double-string, var-eval, func-call)
      -- usable only inside user-defined functions and targets.

----------------------------------------------------------------------------------------------------
SEC 12 -- TOP-LEVEL PROGRAM STRUCTURE
----------------------------------------------------------------------------------------------------

    program ::= { top-level-stmt }
    top-level-stmt ::= pragma-stmt | include-stmt | macro-def | macro-use | option-stmt | func-def
                     | target-def | depload-stmt | assignment-stmt | unset-stmt | deprecate-stmt
                     | arith-stmt | eval-stmt | if-stmt | for-stmt | foreach-stmt | while-stmt
                     | do-whilst-stmt | repeat-until-stmt | loop-stmt | echo-stmt | echoln-stmt
                     | func-call-stmt | run-target-stmt | label-stmt | goto-stmt
    func-call-stmt ::= [ error-suppress ] '$' func-name '(' [ arg-list ] ')'
                        -- same as func-call term but used as a statement for side effects
    -- All constructs valid inside functions/targets are also valid at top (global) scope, except
       label/goto (only meaningful inside functions/targets, though lexically valid anywhere).
       func-def inside a file-scope if-block is valid and is the standard pattern for
       platform-specific function implementations (e.g. inside 'if __os_windows__'; see Sec 11.1).

----------------------------------------------------------------------------------------------------
2.1  Introduction / Toolchain Basics  (01-Introduction.txt)
----------------------------------------------------------------------------------------------------

JxMake is case-sensitive, UTF-8. Empty lines ignored. Uses POSIX directory separator. Avoid reserved
chars <>:"/\|?* in file/dir names; avoid space (can be escaped as '\ ' but not recommended); do not
start/end file/dir names with a space.

CLI: `./jxmake.sh -h` (help). `./jxmake.sh --rm-jxm-cache` or `./jxmake.sh -C <dir> --rm-jxm-cache`
(delete compiled JxMake spec cache files -- do this after updating JxMake libraries if build issues
appear). `./jxmake.sh --rm-prj-cache` / `-C <dir> --rm-prj-cache` (delete ALL project cache files).
Windows: use `jxmake.bat` instead of `jxmake.sh`.

For pragma/include/macro/option statement grammar, see PART 1 Sec 2, 10.6, 10.7.

----------------------------------------------------------------------------------------------------
2.2  Defining Strings  (02-Defining-Strings.txt)  -- see PART 1 Sec 1.5, 3.3 for exact grammar
----------------------------------------------------------------------------------------------------

``  raw: no escapes/vars at all.  ''  single: only \\ and \' recognised, rest literal-with-backslash.
""  double: full var + escape eval.

Evaluating a double-quoted string with variables produces MULTIPLE set members (one per literal
segment / variable substitution), e.g. `"${A} ${B} ${C}"` == `R=${A}; R+=' '; R+=${B}; R+=' '; R+=${C}`
=> 5 members. Consequences (Val:=10):
    echoln "There are ${Val} large rocks."      -- prints correctly; $part_count == 3 if stored
    Val := "There are ${Val} large rocks."      -- prints 'There are There are  large rocks.'
                                                    ($part_count==3; self-referential lazy re-read bug)
    Val := ."There are ${Val} large rocks."     -- prints 'There are 10 large rocks.' ($part_count==3)
    Val := :"There are ${Val} large rocks."     -- prints 'There are 10 large rocks.' ($part_count==1)
WARNING: `Val = 10; Val = "There are ${Val} large rocks."; echoln ${Val}` CRASHES with
`java.lang.StackOverflowError` (infinite lazy self-reference recursion).

Multiline double-quoted string: `[[" ... "]]`; opening `[["` alone on its line, closing `"]]` alone
on its line (nothing before/after either); ALL inner whitespace preserved verbatim; not all
statement contexts accept it.

Calling functions from inside "..." is NOT supported -- no compile error, but the call text is
treated as plain text; use a temp/'local' variable instead.

----------------------------------------------------------------------------------------------------
2.3  Defining Dependency (Prerequisite) List  (03-Defining-Dependency-List.txt)
----------------------------------------------------------------------------------------------------

Prerequisite = another target that must exist / whose code must run first. Dependency = a FILE that
can trigger re-execution of the dependent target (when newer than the target). Every dependency is a
prerequisite; not every prerequisite is a dependency (a prerequisite need not be a physical file).

For C/C++/Java source files, the system recursively AUTO-DETECTS dependencies (headers/sources) and
adds them as prerequisites. Missed dependencies can be added manually inside the target body via
`extradep` (must be the FIRST statements in the target body). Non-existent extradep paths are
discarded from the final prerequisite list by default (use `!` prefix to force-include, PART 1 Sec 10.2).

Dependency lists can also be loaded GLOBALLY from files via `depload`/`sdepload` (safe variant, no
error if missing) -- this DISABLES auto-detection for targets whose deps came from those files. File
format = GNU Make dependency format (like `gcc -M`/`gcc -MM` output), e.g.:
    main.cpp.o: main.cpp all.h sys/sysheader1.h sys/sysheader2.h header1.h header2.h header3.h
All relative paths in the dep file are immediately resolved to absolute paths using the dep file's
own location as reference.

PERFORMANCE: prefer generating dep list files with the `$gdl_*` functions (PART 3) + loading via
`sdepload`, over relying on auto-detection. `$gdl_cpp_module` output MUST be loaded before
`$gdl_cpp_include` output when mixing both (to avoid conflicts).

----------------------------------------------------------------------------------------------------
2.4  Defining Variables  (04-Defining-Variables.txt)  -- see PART 1 Sec 4 for exact grammar
----------------------------------------------------------------------------------------------------

Whitespace outside quotes is a separator (ignored as content). CLI args auto-become constant
variables. A variable's value is stored internally as a SET of member strings; most operations apply
per-member, not to the combined string. `unset` deletes a variable.

Examples of set member counts (lazy '=' unless noted):
    MyVar1 = My Value 1              -> {'My','Value','1'}          (3 members, unquoted whitespace split)
    MyVar1 = 'My Value 1'            -> {'My Value 1'}               (1 member)
    MyVar1 = 'My ' 'Value 1'         -> {'My ', 'Value 1'}           (2 members)
    MyVar2 = "Value is ${MyVar1}"    -> {'Value is ', <MyVar1 val>}  (2 members, lazy)
    MyVar2 := :"Value is ${MyVar1}"  -> {'Value is <val>'}           (1 member, direct+flattened)
    MyVar1 += ' 123'                 -- lazy concat, stacks a member
    MyVar1 :+= ' 456'                -- direct concat, stacks a member
    MyVar1 ?= 123                    -- assigns only if not yet set

Combining (."...") vs flattening (:"..."): flattening ALWAYS collapses a "..." result to ONE member,
frozen at evaluation time, regardless of '='/':=' -- consistent either way. Combining is DIFFERENT
FROM WHAT THE GRAMMAR FILE CLAIMS (tested, see PART 1 Sec 9.1 for full proof): it only collapses to
ONE member and re-evaluates/tracks on each read when reached via LAZY ('=') assignment or used
inline as a bare term (e.g. a function argument). Under DIRECT (':=') assignment, ."..." has NO
EFFECT AT ALL -- it evaluates once and yields the SAME multi-member, frozen result a plain "..."
would under ':='. Do not use ."..." with ':='; use :"..." instead if you want a one-time frozen
single member. Once frozen (flattening) or tracked (lazy combining), later `+=` onto the result var
appends members normally either way.

Local variable value NOT cleared on 'local' declaration: marking a variable 'local' inside a loop
body does not reset any value that was stacked onto it by a previous outer iteration -- `local MyVar`
only marks scope, it does not clear prior content. Watch for this inside nested foreach loops using
`+:=` on a freshly-'local'-marked variable.

Reference (indirect) variables -- `^` prefix (see PART 1 Sec 4.1, 9.7 for grammar):
    VOrg = 10 ; RefA = VOrg ; RefB = ${RefA}
    echoln "'${ RefB}'"     -- prints 'VOrg' (RefB literally holds the string 'VOrg')
    echoln "'${^RefB}'"     -- prints '10'   (indirect: read the var named by RefB's value)
    ^RefB = 20               -- sets VOrg (not RefB) to 20
    RefB = FooVar ; echoln "'${^RefB}'"  -- prints '' (FooVar is undefined)

Deprecating variables: `deprecate <name> [by <replacement>]`. If used inside a function/target where a
LOCAL variable shares the name, the LOCAL one is marked deprecated. Variables originating from
function-call parameters cannot be deprecated.

----------------------------------------------------------------------------------------------------
2.5  Special Variables  (05-Special-Variables.txt)  -- automatic ($[...]) vars: grammar PART 1 Sec 3.2
----------------------------------------------------------------------------------------------------

All special variables below are READ-ONLY and AUTOMATIC (always direct-evaluated; see PART 1 Sec 3.2
note on why lazy '=' is silently treated as ':=' for all of them).

    $[cmdecho]      0/1, mirrors $cmd_echo_off/on state
    $[cmdstreaming] 0/1, mirrors $cmd_streaming_off/on state
    $[lserr]        last suppressed error message; VALUE IS CLEARED after being read
    $[jxmakefile]   the JxMake spec file given on the command line
    $[function]     current user-defined function name (string)
    $[cmdtargets]   all target names given on the command line
    $[usn]          a unique serial number, fresh value every read
    $[target]       the target string
    $[preq^]        count of entire-prerequisite strings
    $[preq*]        the entire prerequisite strings
    $[preq?]        the prerequisite strings newer than the target
    $[preq1]..$[preqN] the 1st..N-th prerequisite string
    $[preq:V]       the ${V}-th prerequisite (V = plain var name holding the 1-based index)
    $[preq+]        manually added extra deps (via extradep)
    $[preq%]        auto-detected extra deps
    $[preq~]        effective extra deps ($[preq+] + $[preq%] not already in $[preq*])
    $[excode]       exit code of the preceding '@' shell block
    $[stderr]       stderr of the preceding '@' shell block (whole capture = ONE set member; use
                     $explode(...,"\n") to split into lines)
    $[stdout]       stdout of the preceding '@' shell block (same one-member-capture note)
    -- $[preq+]/$[preq%]/$[preq~] only see deps from depload/sdepload/auto-detection/extradep.
    -- Reading $[excode]/$[stderr]/$[stdout] FLUSHES all pending buffered '@' commands;
       reading $[lserr] does NOT flush pending commands.

Special variable shortcuts (__xxx__, no ${} needed; read-only unless marked Writable):
    __jxm_ver_major__(0x0000-FFFF) __jxm_ver_minor__(0x00-FF) __jxm_ver_patch__(0x00-FF)
    __jxm_ver_value__(0xJJJJNNPP)  __jxm_ver_devel__('alpha1'/'beta1'/'rc1'/...)
    __os_name__ (normalized OS name)   __os_name_actual__ (actual OS name)
    __os_windows__ __os_posix__ __os_linux__ __os_bsd__ __os_mac__ __os_cygwin__ __os_mingw__
    __os_msys__ __os_posix_compat__   (each: non-zero if that OS/environment)
    __os_arch__ (OS architecture string)  __os_bit_count__ (non-zero = bit count)
    __os_32bit__ __os_64bit__ __os_be__ (big-endian) __os_le__ (little-endian)   (each: non-zero flag)
    __os_dsep_char__ (dir separator)  __os_psep_char__ (path-list separator)
    __re_all__          regex string '.+'
    __c_use_dark__ __c_use_light__   1 if that color theme active
    __c_clrscr__ __c_black__ __c_dgray__ __c_lgray__ __c_red__ __c_green__ __c_yellow__ __c_blue__
    __c_magenta__ __c_cyan__ __c_white__ __c_reset__   (ANSI escape codes; black/white/dgray/lgray
                    auto-invert between dark/light theme so text stays visible)
    WRITABLE:
    __include_paths__  [C/C++] extra search paths for recursive dependency auto-detection
    __class_paths__    [Java]  extra search paths for recursive dependency auto-detection
    -- put only USER paths here; add system paths via library features instead.
    -- 'local' prefix scopes the modification to current function/target.
    -- For the target body's modifications to affect auto-detection: all assignments must occur
       BEFORE any other statement (but after 'extradep' if present) and NOT inside conditional/loop
       blocks.
    -- New paths added after '*.dep.cache' files already exist do NOT trigger cache rebuild; only fix
       is deleting project cache files ($clear_project(), or CLI `--rm-prj-cache`).

----------------------------------------------------------------------------------------------------
2.6  Regular Expression in Variable  (06-Regular-Expression-In-Variable.txt) -- grammar: PART 1 Sec 6
----------------------------------------------------------------------------------------------------

    <dst> = ${<src>/<regexp>/[replacement]/}      <dst> = $[<src>/<regexp>/[replacement]/]
Uses Java regex (https://docs.oracle.com/javase/8/docs/api/java/util/regex/Pattern.html). Example
gotcha -- prefer `(.+)` over `(.*)`:
    Val = a ; Val += b
    $implode(${Val/(.*).o/$1.cpp/})   -- with input 'a.o','b.o': prints 'a.cpp b.cpp' (fine here)
    $implode(${Val/(.*)/$1.cpp/})     -- prints 'a.cpp.cpp b.cpp.cpp'  (BAD: (.*) double-matches)
    $implode(${Val/(.+)/$1.cpp/})     -- prints 'a.cpp b.cpp'          (GOOD)
Refer to a plain variable from the replacement string by escaping: `\${VarName}` (plain names only;
no special vars; no nested regex). For heavier regex work use the `$re_*` built-ins (PART 3) instead
of this in-variable form.

2.7  User-Defined Function  (08-User-Defined-Function.txt)  -- grammar: PART 1 Sec 8
----------------------------------------------------------------------------------------------------

    function <name>( [param[,...]] ) [supersede] [deprecated [by <repl_func>]]
        ...
        return <value>
    endfunction
    <result> := $call( <name>, [arg...] )     -- may recursively call other user functions; NO shell commands
    <result> := $exec( <name>, [arg...] )     -- may run shell '@' commands; CANNOT call other user functions

Optional params: prefix with `?`; all params after the first optional must also be optional. To pass
a partial set of optional args, use bare `?` (no quotes) to request the default for that slot:
    function my_function(par1, par2, ?opt1, ?opt2, ?opt3)
        local opt1 :?= 'opt1' ; local opt2 :?= 'opt2' ; local opt3 :?= 'opt3'
        $printf("'%-6s %-6s %-6s %-6s %-6s'\n", ${par1}, ${par2}, ${opt1}, ${opt2}, ${opt3})
    endfunction
    $call(my_function,'a1','a2')                    -> 'a1     a2     opt1   opt2   opt3  '
    $call(my_function,'a1','a2','a3','a4')          -> 'a1     a2     a3     a4     opt3  '
    $call(my_function,'a1','a2','a3','a4','a5')     -> 'a1     a2     a3     a4     a5    '
    $call(my_function,'a1','a2',?,?,'a5')           -> 'a1     a2     opt1   opt2   a5    '
    $call(my_function,'a1','a2','???','?','a5')     -> 'a1     a2     ???    ?      a5    '  (literal
                                                          strings, not defaults -- only a bare unquoted
                                                          single '?' means "use default")

`supersede`: replaces any earlier same-named function; `$call(__origin__, ...)` inside the superseding
function invokes the PREVIOUS definition in the chain; the superseding function may declare DIFFERENT
parameters than the one it replaces.

Priority reading vars/params: function params > global vars (same name); local vars (on declaration)
> global vars; local vars (on declaration) > function params. Inheritance: caller's params AND local
vars are IMPLICITLY inherited by the callee as extra by-value args UNLESS the callee declares its own
required/optional param of the same name.

$exec bodies -- all shell commands prefixed '@' (see PART 1 Sec 8.2/8.3 for exec-stmt/env-modifier
grammar). Passing function-call results as command text is unsupported -- precompute into a
temp/'local' var first. Always prefer absolute paths in command args (CWD is switched to the script's
CWD before exec, but don't rely on relative paths). `$[excode]`/`$[stderr]`/`$[stdout]` hold the last
combined result; check `$[excode]` after every command sequence.

2.8  Targets  (09-Targets.txt)  -- grammar: PART 1 Sec 10.2, 10.3
----------------------------------------------------------------------------------------------------

    target <name> [: prerequisite...]
        [extradep [<specific_target>:] [!]<path>...]
        ...
    endtarget

Pattern rules (glob): target name `?`=one char, `%`=multiple chars; in prereq name, `%` = the
captured portion of target-name `?`/`%` (sequential); `%1`-`%9` address specific captures directly.

    target %.cpp.o : %.cpp ... endtarget
    target build/mylib.a : build/mylib/%.cpp.o ... endtarget
    target %.o : %.1.asm %.2.asm
        extradep        special_include1.asm      # applies to all '%.o'
        extradep z.o :  special_include2.asm       # only 'z.o'
        extradep z.o : !special_include3.asm       # only 'z.o'; force-include even if non-existent now
    endtarget

Force a target to always run even if a same-named directory/file exists, via `.PHONY`:
    target build : .PHONY ... endtarget
    target .PHONY endtarget      -- the name does not have to literally be '.PHONY'

Running other targets: `jxmake t1 t2 t3` (sequential; same as three separate `jxmake t` lines) vs
`+jxmake t1` / `+jxmake t2` / ... / `jxwait` (parallel; queues each target, `jxwait` blocks until all
queued `+jxmake` targets finish). Omitting `jxwait` after `+jxmake` calls risks undefined
results/errors from subsequent non-'+' `jxmake` calls, and the program may terminate before the
parallel targets fully finish.
TESTED: '+jxmake' completion order is NOT guaranteed to match queuing order (genuinely parallel, a
race). Given `+jxmake b` queued before `+jxmake c`, then `jxwait`, real output was 'Target A' (the
queuing target's own body, runs first/synchronously) then 'Target C' then 'Target B' -- c finished
before b despite being queued second. Never rely on '+jxmake' completion order; use `jxwait` and
treat all queued parallel targets as unordered relative to each other.

Target/prereq names commonly use the flattening operator to interpolate variables safely:
    EXE_EXT=elf ; PROG_NAME=:"main.${EXE_EXT}"
    target ${PROG_NAME} : ${OBJ_FILES} ... endtarget
    target :"%.cpp.${OBJ_EXT}" : %.cpp ... endtarget

2.9  Flow Control  (10-Flow-Control.txt)  -- grammar: PART 1 Sec 11.1, 11.3 (fully covers this topic)

One-liner-if RHS accepts the FULL run-target-stmt ('jxmake' / '+jxmake' / 'jxwait'), not just plain
'jxmake' -- tested and confirmed against real output:
    target a
        local X := 0
        if ${X} == 0 : +jxmake b
        if ${X} == 0 : +jxmake c
        if ${X} == 0 :  jxwait
    endtarget
    # actual output: 'Target A' then 'Target C' then 'Target B' -- see PART 2 Sec 2.8 for what this

2.10  Loop  (11-Loop.txt)  -- grammar: PART 1 Sec 11.2
----------------------------------------------------------------------------------------------------

CAUTION pattern -- comparing elapsed time against a timeout: do NOT precompute an absolute end-time
via `add End, ${Start}, 1000000` and loop `while true ... if $micros() >= ${End} : break` (numeric
overflow risk on the sum). Prefer computing the delta each iteration instead:
    Start := $micros()
    while true
        Current := $micros()
        sub Delta, ${Current}, ${Start}
        if ${Delta} > 1000000 : break
    endwhile

2.13  Simple Programmer Hardware  (14-Simple-Programmer-Hardware.txt)
----------------------------------------------------------------------------------------------------

Wiring/connection reference for simple in-circuit programmers built from a USB-serial/USB-ISS/
USB-GPIO adapter. Format below: `<host_pin> --[series resistor]--> <target_pin>` per programming
protocol; VCC/GND connect directly unless noted. Max load noted per adapter.

USB-ISS adapter (~30mA max load):
    -> ISP:  IO4--220R-->MISO, IO3--220R-->SCK, IO2--220R-->MOSI, IO1--220R-->nRST, VCC->VCC, GND->GND
    -> TPI:  IO4--220R-->DATA (shared node w/ CLK path), IO3--220R-->CLK (same node as DATA via IO4),
             IO2--2.2k-->EN_JUMPER-->DATA node, IO1--220R-->nRST, VCC->VCC, GND->GND
             (IO4 and IO3 220R resistors join at a common node that is both the DATA and CLK line
             into the EN_JUMPER-gated 2.2k from IO2; see source ASCII diagram for exact topology)

JxMake DASA adapter (USB-Serial; ~300mA max load):
    -> ISP:  CTS--220R-->MISO, DTR--220R-->SCK, RTS--220R-->MOSI, TXD--220R-->nRST, VCC->VCC, GND->GND
    -> TPI:  CTS--220R-->DATA node (shared w/ CLK), DTR--220R-->CLK node, RTS--2.2k-->EN_JUMPER-->DATA
             node, TXD--220R-->nRST, VCC->VCC, GND->GND
    -> UPDI: RXD--470R-->UPDI, TXD--[Schottky diode]--EN_JUMPER--> same UPDI node, VCC->VCC, GND->GND

JxMake USB-GPIO Module (~300mA max load):
    -> ISP:  MISO--330R-->MISO, SCK--330R-->SCK, MOSI--330R-->MOSI, SS--330R-->nRST, VCC->VCC, GND->GND
    -> TPI:  MISO--330R-->DATA node (shared w/ CLK), SCK--330R-->CLK node, MOSI--1.0k-->EN_JUMPER-->
             DATA node, SS--330R-->nRST, VCC->VCC, GND->GND
    -> UPDI: RXD--470R-->UPDI, TXD--[Schottky]--EN_JUMPER--> same UPDI node, VCC->VCC, GND->GND
    -> PDI:  VCC through 3V3 regulator -> target VCC. RXD--820R--(node A, w/ Zener 3V6 0.25/0.5W to
             GND)--220R-->DATA; TXD--EN_JUMPER--820R-->(node A)--220R-->DATA (RXD/TXD share the DATA
             line through this network); XCK--820R--(node B, w/ Zener 3V6 0.25/0.5W to GND)-->CLK.
    -> SWD/SWIM/LGT8-SWD: VCC via 3V3 regulator. MISO--330R--[74LVC541 buffer, +3V3, 4k7 pull]-->
             (fans out to) SWDIO/SWIM/LGT8-SWD AND (via EN_JUMPER + 470R) same node. MOSI--330R--
             [74LVC541]--100R-->nRST. SCK--330R--[74LVC541]--100R-->SWCLK/LGT8-SWC.
             NOTE: tie 74LVC541 OE1/OE2 to GND; unused buffer inputs to GND/+3V3 via 4k7. For 5V
             targets: use 74HC541 + 680R instead of 74LVC541 + 470R, and drop the 3V3 regulator.
             Other compatible 74XX buffer ICs may be substituted.
    -> PIC ICSP 3.3V: VCC via 3V3 regulator. MISO--220R--[74LVC541,+3V3,4k7]-->PGD (w/ EN_JUMPER+680R
             tap). MOSI--220R--[74LVC541]--150R-->nMCLR. SCK--220R--[74LVC541]--150R-->PGC.
             TX--220R--[74LVC541]--150R-->PGM. Same 74LVC541 OE/pull-up notes as above.
    -> PIC ICSP 5V: no regulator (direct VCC). MISO--220R--[74HC541,+5V,4k7]-->PGD (EN_JUMPER+1k tap).
             MOSI--220R--[74HC541]--220R-->nMCLR. SCK--220R--[74HC541]--220R-->PGC.
             TX--220R--[74HC541]--220R-->PGM. Same OE/pull-up notes (74HC541, +5V). Since both sides
             are 5V, the buffer IC and left-side resistors can be omitted entirely.

PIC High-Voltage Add-On (from programmer's +5V/+VPP rails to target nMCLR/VPP): nMCLR through 1k to a
BC547 transistor base network (with 1N4148 diode from +VPP through 22k/4k7 divider, optional 5pF cap
and optional left-side Schottky) driving the target's nMCLR/VPP pin through a right-side Schottky
diode, 0M1 (100k) resistor, and a RESET push-button/10uF cap network to GND. VPP can range ~8-13V
depending on target PIC; a common approach is +13V5 as VPP plus a correctly-rated Zener across the
100k resistor, or substitute a smaller resistor for the 100k to form a divider with the 4k7 that
reduces VPP further. The LEFT-side Schottky is ALWAYS REQUIRED for the "JxMake Versatile MCU
Programmer" (USB-GPIO Module II + Logic Level Translator). Other compatible parts may be substituted.
    WARNING: most PIC MCUs that only support 3V3-and-lower supply voltages do NOT support high
    voltage programming -- do not attempt this add-on with such parts.

PART 3 -- BUILT-IN FUNCTIONS  (from 07-Built-In-Functions.txt + 99-Appendix-X schemas)
====================================================================================================

Call syntax: `<result_var> = $function_name( [argument...] )`. Every call is its own statement (no
nesting two calls in one statement; use temp/'local' vars). Prefix `-` suppresses runtime errors
(message to stderr); `$call`/`$exec` cannot be prefixed `-`. See NOTATION TEMPLATE in the file header
for the `$name(params) -> ret_type` / "# notes" format used below, and for the type-token glossary.

Cross-cutting behavioral notes that apply to many entries below (kept inline per-entry as
"(flatten: ...)" / "(bool-word: ...)" tags rather than as separate tables):
  - "flatten: <args>" = that argument's set members are internally flattened to ONE string before
    the function uses it (multi-member sets passed there collapse silently).
  - "bool-word: <args>" = that argument accepts the words 'true'/'false' (internally mapped to 1/0)
    in addition to numeric 0/1.
  - $bse_wr_* functions are more stringent about validating/reporting errors on <input_value> than
    other functions.
  - HTTP functions do not support cookies. `$ssl_trust_all` disables certificate validation --
    security risk (MITM); prefer importing certs into the JVM truststore via `keytool` instead
    (see https://docs.oracle.com/javase/8/docs/technotes/tools/windows/keytool.html and later JDK
    keytool docs, and https://stackoverflow.com/a/2893932).

---- call / exec ----
$call(user_function_name:str, [arg:term...]) -> output_value
    # call a user-defined function (no OS commands allowed in it); (flatten: user_function_name)
$exec(user_function_name:str, [arg:term...]) -> output_value

$mcu_prog_exec(bend_spec:set, prg_spec:set, mcu_sig:set, cmds:set, fwc_handle:handle:fwc, empty_byte:int) -> output_value

    # <bend_spec> = { <backend_name>[, parameter...] } (spaces/dashes in backend_name -> '_'):
    #   'USB-ISS'                       : { name, serial_device_name }
    #   'DASA' | 'JxMake DASA'          : { name, serial_device_name }
    #   'USB-GPIO' | 'JxMake USB-GPIO'  : { name, primary_serial_device_name, secondary_serial_device_name, auto_notify_error_message }
    #     ('' for primary + a pair number for secondary auto-connects to the Nth JxMake USB-GPIO module;
    #     detection may be unreliable with multiple modules on the same external USB hub)
    #   Some <prg_spec> values don't need a backend -- pass '' for <bend_spec> in that case (noted per prg_spec below).
    # <prg_spec> = { <programmer_name>, parameter... } (spaces/dashes in programmer_name -> '_'):
    #   'ProgISP'        : { name, config_json (see $mcu_prog_cfg_json), UNUSED, spi_clock_frequency }
    #   'ProgTPI'        : { name, config_json, UNUSED, baudrate }
    #   'ProgUPDI'       : { name, config_json, UNUSED, baudrate }
    #   'ProgPDI'        : { name, config_json, UNUSED, baudrate }
    #   'ProgSWIM'       : { name, config_json, UNUSED, UNUSED }
    #   'ProgSWD'        : { name, config_json, UNUSED, swd_clock_frequency, [index_to_default_multidrop_id (1-based)], [multidrop_id...] }
    #   'ProgPIC16'      : { name, config_json, UNUSED, pgc_frequency (currently ignored) }
    #   'ProgPIC18'      : { name, config_json, UNUSED, pgc_frequency }
    #   'ProgPIC24'      : { name, config_json, UNUSED, pgc_frequency }
    #   'ProgDSPIC30'    : { name, config_json, UNUSED, pgc_frequency (ignored in non-EICSP mode) }
    #   'ProgJTAG'       : { name, UNUSED, UNUSED, tck_default_clock_frequency }
    #   'ProgBootAVR109'      (bend_spec:='') : { name, config_json, target_serial_device_name, magic_baudrate_or_baudrate }
    #     (>0: explicit magic baudrate to trigger CDC ACM bootloader; 0..-2400 inclusive: replaced with
    #     default magic baudrate; <-2400: not a CDC ACM bootloader target, converted to positive before use)
    #   'ProgBootSTK500'      (bend_spec:='') : { name, config_json, target_serial_device_name, baudrate }
    #   'ProgBootSTK500v2'    (bend_spec:='') : { name, config_json, target_serial_device_name, baudrate }
    #   'ProgBootChip45B2'    (bend_spec:='') : { name, config_json, target_serial_device_name, baudrate, rs485 (<=0: normal serial mode) }
    #   'ProgBootChip45B3'    (bend_spec:='') : { name, config_json, target_serial_device_name, baudrate, rs485_address (<=0: normal serial), [XTEA_key1_UInt32, XTEA_key2_UInt32, XTEA_key3_UInt32, XTEA_key4_UInt32] }
    #   'ProgBootTSB'         (bend_spec:='') : { name, config_json, target_serial_device_name, baudrate, [current_password], [new_password] }
    #   'ProgBootURCLOCK'     (bend_spec:='') : { name, config_json, target_serial_device_name, baudrate }
    #   'ProgBootSTM32Serial'  (bend_spec:='') : { name, config_json, target_serial_device_name, baudrate, go_address (<0: default 0x08000000) }
    #   'ProgBootSTM32DFU' [TODO]  (bend_spec:='') : { name, config_json, [vid], [pid], [serial_number] }
    #   'ProgBootLUFAPrinter' (bend_spec:='') : { name, lufa_printer_name }
    #   'ProgBootAVRDFU' [TODO]    (bend_spec:='') : { name, config_json, [vid], [pid], [serial_number] }
    #   'ProgBootOpenBLT'     (bend_spec:='') : { name, config_json, target_serial_device_name,
    #     baudrate (negative: enable UART checksum), flash_base_address (<0: default 0x00000000/callback),
    #     bootloader_size (<0: default 0x2000/callback), user_prog_vector_table_size (<0: default 0x0000/callback),
    #     [key,...] } (use "cb:<callback_function_name>" instead of a fixed key to use a user callback;
    #     callback receives (requestType, requestParam): 1=REQ_FLASH_BASE_ADDR, 2=REQ_BOOTLOADER_SIZE,
    #     3=REQ_UPROG_VTAB_SIZE(sic, uses code 2 in source example), 9=REQ_KEY_FROM_SEED (requestParam<1> - 1 = derived key))
    #   'ProgBootSAMBA'       (bend_spec:='') : { name, config_json, target_serial_device_name, baudrate, magic_baudrate (usually 1200) }
    #   'ProgBootUSBasp' [TODO] (bend_spec:='') : { name, config_json, [vid], [pid], [manufacturer_string], [product_string], [serial_number] }
    #   <target_serial_device_name> supports 3 string forms: plain device path (e.g. '/dev/ttyUSB0');
    #     JxMake USB-GPIO descriptor 'jxm:<primary_serial_device>:<secondary_serial_device>' (e.g.
    #     'jxm:COM15:COM16'); serial-over-network descriptor
    #     'net:<hostNameOrIP>:<uploadPort>:[urlSetBaudrate_printfFormat]' (e.g.
    #     'net:esp-link.local:2323:console/baud?rate=%d').
    # <mcu_sig> = set of numbers identifying the MCU (e.g. {0x1E,0x95,0x0F} for ATmega328P;
    #   {0x10,0x80} for PIC18F4520; -1 for STM8 which has no signature). ProgJTAG ignores this: pass -1.
    # <cmds> = set of command-name strings (+ inline params where noted), each documented as
    #   Purpose/Parameters/Return/NOTE:
    #     no_operation()                                  -- do nothing
    #     chip_erase()                                    -- erase chip
    #     read_flash(start_address,number_of_bytes) -> firmware bytes
    #     write_flash()                                   -- write fwc_handle's firmware to flash
    #                                                         (same as write_flash_application_section for ProgPDI)
    #     write_flash_boot_section()          -- ProgPDI ONLY -- write to flash boot section
    #     write_flash_application_section()   -- ProgPDI ONLY -- write to flash application section
    #     verify_flash()                                  -- compare fwc_handle firmware vs. flash
    #     read_eeprom(address) -> byte value
    #     write_eeprom(address,value)
    #     write_embedded_eeprom()             -- ProgPIC* ONLY -- write EEPROM bytes embedded in the firmware binary
    #     read_fuses() -> fuse byte(s)                    -- fuse bytes are MCU-specific, see datasheet
    #     write_fuses(byte[,...])                          -- fuse bytes are MCU-specific, see datasheet
    #     write_embedded_fuses()              -- ProgPIC* ONLY -- write fuse byte(s) embedded in firmware
    #     read_lockbits() -> lock bits                    -- NOT AVAILABLE for ProgPIC*

$mcu_prog_exec() Alternative INI Config Format (for <configuration_json_string> args above):
    # An INI-like alternative to the JSON config string, produced/consumed via $mcu_prog_cfg_ini().
    # Rules: (1) ';' starts a comment, rest of line ignored. (2) exactly ONE section header
    #   '[CLASS:<fully.qualified.RootConfigClassName>[@<version_uid>]]' before any key-value pairs.
    #   (3) key=value pairs after the header; undefined keys keep the class default. Key = text
    #   before the first '=' (whitespace ignored except inside ""); dot (.) separates sub-fields.
    #   Value = text after the first '=' (whitespace ignored except inside ""); array elements
    #   comma-separated; numbers decimal or hex; booleans true/false only; enums = Java enum name
    #   string; 'null' allowed where the field supports it. Unlike JSON (always literal), INI values
    #   support CONSTANT NAMES (public static final fields of the hosting class, referenced as
    #   `fully.qualified.HostClass:::CONST_NAME`; names needing translation are prefixed '$', those
    #   that don't are written plainly) and SPECIAL FUNCTIONS (`$<func_name>:<param>`); both are
    #   class-specific -- currently only 'ProgPIC16.Config' supports them (constants list and
    #   $VI:<N> / $TC:<VV> special functions given below). (4) SHORTCUTS: define with
    #   `#define ::: <name> = <value>`; use with `#{<name>}`; use sparingly (INIEncoderLite itself
    #   defines none). (5) trailing '\' continues onto the next line (applied AFTER comment removal).
    #   (6) case-sensitive throughout. Format is currently designed for $mcu_prog_cfg_ini() strings
    #   only; other INI strings may or may not parse correctly; missing keys use class defaults.
    # ProgPIC16.Config constant names (for PIC10/PIC12/PIC16): $_INVALID_, $CS_NotSupported, $CS_NOP,
    #   $CS_DelayMS, $CS_ResetAddress, $CS_SetAddress, $CS_IncAddress, $CS_BitwiseAND, $CS_BitwiseOR,
    #   $CS_ErrIfCmpEQ, $CS_ErrIfCmpNEQ, $CS_Print2Chars, $CS_PrintSDecNN, $CS_PrintSDec03,
    #   $CS_PrintSDec05, $CS_PrintUDecNN, $CS_PrintUDec03, $CS_PrintUDec05, $CS_PrintUHexNN,
    #   $CS_PrintUHex02, $CS_PrintUHex04, $CS_PrintNL, $LoadConfiguration, $LoadDataForProgMem,
    #   $LoadDataForDataMem, $IncrementAddress, $ResetAddress, $ReadDataFromProgMem,
    #   $ReadDataFromDataMem, $BeginErase, $BeginEraseProgCycle, $BeginProgOnlyCycle,
    #   $BeginIntTimedProg, $BeginExtTimedProg, $EndExtTimedProg, $RowEraseProgMem, $BulkEraseProgMem,
    #   $BulkEraseDataMem, $BulkEraseSetup1, $BulkEraseSetup2, $ChipErase, $BeginProgramming,
    #   $EndProgramming, $TogSelEvenRows1 (alias of $BulkEraseSetup1), $TogSelEvenRows2 (alias of $BulkEraseSetup2)
    # ProgPIC16.Config special functions: $VI:<N> (variable index N) | $TC:<VV> (2-char sequence;
    #   each char may be a \uNNNN escape), e.g. $VI:0, $VI:1, $TC:AB, $TC:A , $TC: B
    # full worked INI example: docs/txt/en_US/99-Appendix-X_Built-In-Function-Parameters.txt § $mcu_prog_cfg_ini()
    # full worked constant/function-substitution examples: same file § "Alternative to Configuration
    #   JSON Strings" and § "shortcut" sections

---- Java source preprocessor ----
$pp_java_scf(path_inp:path, path_out:path, cond_flags:set, sval_map_handle:handle:map)
    # preprocess a Java source file; (flatten: path_inp,path_out,sval_map_handle)
    # Directives inside the source:
    #     #if [!]<condition_flag>  ...  #endif
    #     #if [!]<condition_flag>  ...  #else  ...  #endif
    #     ... #subst{<substitution_id>} ...
    #   <condition_flag> ::= 'true' | 'false' | <number> | <symbol_name>  (symbol truthy if present in cond_flags)
    #   <substitution_id> ::= <symbol_name>  (looked up in sval_map_handle via $map_get)
    # A trailing single-line comment on a directive line IS allowed; multiline (* *) comments must
    # NOT cross/intersect a directive line (must be entirely on one line); trailing '\' line
    # continuation is NOT supported on directive lines.
    # Usage pattern: local cflags := __MY_CONDITION_1__ __MY_CONDITION_2__ ; local svals := $map_new()
    #   ; $map_add(${svals},'MY_SUBST_ID_1','"abc"') ; $pp_java_scf('In.java.in','Out.java',${cflags},${svals})
    #   ; $map_delete(${svals})
    # full worked example: docs/txt/en_US/07-Built-In-Functions.txt "Using the Simple Java Source
    #   Code Preprocessor" section (kept in source form there; small enough not to need an appendix pointer)

---- function-call shortcuts (grammar: see PART 1 Sec 9.3, 9.4, 9.6) ----
    ~${V} / ~$[V]   -> $path_ndsep($cat_path($cwd(),V))   (cwd-relative path)
    ^${V} / ^$[V]   -> $path_ndsep($cat_path($ptd(),V))   (ptd-relative path)
    -${V} / -$[V]   -> $path_ndsep($rel_path(V))          (path to relative)
    ${V}<n> / ${V}<n,o> / ${V}<b:e>  -> $partn(...)/$partnm(...)   (and $[V] forms)
    {{ v, ... }}    -> $stack(v, ...)
    -- path shortcuts use auto-generated temp vars: ALWAYS store results with ':=' (never lazy '=');
       unlike ordinary function calls, path shortcuts ARE evaluated inside double-quoted strings.
    -- $partn/$partnm and $stack shortcuts do NOT use temp vars -- they expand directly to function
       calls and are NOT evaluated inside plain double-quoted strings (they ARE evaluated inside
       ."..." or :"...").

---- worked micro-examples preserved from source (illustrate placement rules above) ----
    # NOT supported (func call in plain "..." is literal text, not evaluated):
    R := "123 $ucase(${A}) ${B}"
    # NOT supported (compile error -- bare terms cannot follow a quoted string without an operator):
    R := '123' $ucase(${A}) ${B}
    # Supported alternative:
    R = '123' ; R :+= $ucase(${A}) ; R += ${B}
    # NOT supported (compile error -- function call arg cannot be a plain "..."):
    R := $lcase("${A} ${B}")
    # Supported:
    C = "${A} ${B}" ; R := $lcase(${C})            # via temp var
    R := $lcase(."${A} ${B}")                       # via combining operator
    R := $lcase(:"${A} ${B}")                       # via flattening operator
    -$rmdir('mydir')                                 # suppress error
    # NOT supported (compile error -- partn shortcut cannot appear as a bare echo argument mixed with text):
    echoln 'The value is ' ${A}<I>
    # Supported (wrap in $stack instead):
    echoln $stack('The value is ', ${A}<I>)
    # { } is a set-creation operator (SUGAR) only in function-argument/return/extradep/prereq/foreach
    # contexts; elsewhere '{'/'}' inside an expression are literal characters:
    Val := { A 1 2 } ; echoln $part_count(${Val})     # prints '5' (not 3 -- { and } counted as members)
    echoln { A 1 2 }                                   # here, NOT a set-creation operator (bare stmt context)
    echoln $lcase({ A 1 2 })                            # here, IS a set-creation operator (function arg)
    return { A 1 2 }                                    # set-creation operator
    Val := {{ A, 1, 2 }} ; echoln $part_count(${Val})  # prints '3' ({{ }} = $stack shortcut)
    echoln "{ abc 123 }" ; echoln "{{ abc, 123 }}"       # inside "...", { }/{{ }} are always literal text
