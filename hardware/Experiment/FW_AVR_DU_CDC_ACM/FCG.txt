## NOTES

1. WaitUntilRMWDone() spin-loop: Several inline functions in usb_peripheral_avr_du.h call
   WaitUntilRMWDone() before STATUS register writes. This spin runs in interrupt context
   (ISR(USB0_TRNCOMPL_vect) path). The errata says it completes within 14 cycles, but
   any function that touches STATUS registers should be flagged MAYBE ⚠️ for latency
   analysis on congested paths.

2. EndpointBufferSet alignment guard (errata): EndpointBufferSet silently returns without
   setting the buffer pointer if the OUT buffer address is odd. This is a known AVR DU
   errata workaround. All callers must ensure word-aligned OUT buffers; the silence makes
   this a latent bug if alignment is ever violated.

3. usb_stop() vs USB_Stop(): inc_usb_avr_du.h defines usb_stop() (static, lowercase) which
   duplicates most of USB_Stop() (usb_core.c). usb_stop() is taken by address via
   (void) usb_stop; in usb_init() to avoid an unused-function warning — it is never
   actually called at runtime in the loopback demo. USB_Stop() is the live path called
   from USB_Reset().

4. USB_CDCRequestHandler called from USB_SetupProcess (usb_core.c), not from
   inc_usb_avr_du.h directly. The USB0_TRNCOMPL_vect ISR → USB_TransferHandler →
   USB_ControlSetupReceived → USB_SetupProcess → USB_CDCRequestHandler is the live
   CDC control path.

5. SetupDeviceRequestGetDescriptor has two implementations guarded by #if 0 / #else.
   The active implementation (else branch) is the simplified version. The #if 0 block is
   dead code; it does not affect the call graph but adds maintenance confusion.

6. Depth stops for USB_Reset callees (USB_Stop, USB_PeripheralInitialize,
   USB_ControlEndpointsInit, USB_ControlTransferReset) are all due to the 3-level limit
   from the ISR entry. Their internal call graphs are documented in Sections 8–11 via
   the usb_start / usb_stop paths which share the same callees.

7. USB_PipeTransactionComplete (called from USB_TransferHandler) calls
   USB_InTransactionRun, USB_OutTransactionRun, and USB_PipeTransferEndCallback
   at depth 4 from the ISR. These are already documented in Sections 6–7 (via the
   USB_TransferWriteStart / USB_TransferReadStart paths).

## BATCH 6: MODULO → BITWISE-AND REPLACEMENT — DONE! (7266 → 7230, −36 bytes)
==============================================================================

All USB endpoint sizes are always powers of 2 (8, 64, ...) because:
  - ConvertEndpointSizeToMask validates IsPowerOfTwo(endpointSize) before configuring
  - USB_EndpointSizeGet returns 8U << sizeCode, always a power of 2

For power-of-2 n: (x % n == 0) ≡ (x & (n-1) == 0). This allows replacing all
three 16-bit modulo operations with bitwise AND, eliminating the __udivmodhi4
software division library routine entirely.

USB_InTransactionRun (usb_peripheral_read_write.c):
  DONE! nextTransactionSize % endpointSize → nextTransactionSize & (endpointSize - 1U)

USB_OutTransactionRun (usb_peripheral_read_write.c):
  DONE! nextTransactionSize % endpointSize → nextTransactionSize & (endpointSize - 1u)

USB_PipeTransactionComplete (usb_peripheral_read_write.c):
  DONE! transactionSize % USB_EndpointSizeGet(pipe) → transactionSize & (USB_EndpointSizeGet(pipe) - 1u)

Result: __udivmodhi4 (40 bytes) eliminated by --gc-sections. Each call site grew +2 bytes
due to the subtraction instruction, but net savings = −36 bytes (7266 → 7230).
