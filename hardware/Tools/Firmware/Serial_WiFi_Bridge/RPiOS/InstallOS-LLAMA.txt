----------------------------------------------------------------------------------------------------
Installing BLIS
----------------------------------------------------------------------------------------------------

##### On the RPi (SSH Session) #####

Make the boot and root partion writeable first:
    boot-rw.sh
    root-rw.sh

Install dependencies:
    sudo apt update
    sudo apt install cmake libomp-dev libcurl4-openssl-dev

Reboot the RPi (if required):
    sudo reboot
    root-rw.sh

Build and install BLIS:

    cd /mnt/data/pi/llama
    tar -xzvpf blis-2.0.tar.gz

    cd blis-2.0
    CFLAGS="-O3 -mcpu=cortex-a76" ./configure --enable-cblas -t openmp,pthreads auto

    make
    sudo make install

Reboot the RPi (if required):
    sudo reboot


----------------------------------------------------------------------------------------------------
Installing llama.cpp
----------------------------------------------------------------------------------------------------

##### On the RPi (SSH Session) #####

Make the data partion writeable first:
    data-rw.sh

Build llama.cpp:

    cd /mnt/data/pi/llama
    tar -xzvpf llama.cpp-b9753.tar.gz

    cd llama.cpp-b9753

    cmake -B build -DGGML_BLAS=ON -DGGML_BLAS_VENDOR=FLAME -DCMAKE_BUILD_TYPE=Release -DGGML_NATIVE=ON -DGGML_LTO=ON
    cmake --build build --config Release

##### On the RPi (SSH Session) #####

Make the data partion writeable first:
    data-rw.sh

Execute:
    nano /mnt/data/pi/llama/run_llama.sh
and fill it with (without the preceding indent):

    #!/usr/bin/env bash
    set -euo pipefail

    # Disable swap — model weights must stay in RAM
    sudo swapoff -a

    # Enable huge pages (2 MB instead of 4 KB) for the model weight allocation.
    # 'madvise' mode only applies to processes that request it — llama.cpp does.
    # This reduces TLB pressure during matrix multiplications.
    # THP requires CONFIG_TRANSPARENT_HUGEPAGE in the kernel; skip silently if absent.
    THP=/sys/kernel/mm/transparent_hugepage/enabled
    [[ -f "$THP" ]] && echo madvise | sudo tee "$THP" > /dev/null

    WORKDIR=/mnt/data/pi/llama
    MODEL_PATH=$WORKDIR/qwen3-1.7b-q4_k_m.gguf
    MODEL_PATH=$WORKDIR/qwen2.5-coder-3b-instruct-q4_k_m.gguf
    BINARY=$WORKDIR/llama.cpp-b9753/build/bin/llama-server

    LLAMA_ARGS=(
        -m "${MODEL_PATH}"
        -c 2048
        --port 8080 --host 0.0.0.0
        --temp 0.6
        --threads 3                # Best throughput on Pi 5 for this model (benchmarked)
        --mlock                    # Pin model pages in RAM; prevents any partial eviction
    )

    # Suppress nested parallelism — llama.cpp owns its threads; BLAS/OMP must stay out of the way
    export BLIS_NUM_THREADS=1
    export OPENBLAS_NUM_THREADS=1
    export OMP_NUM_THREADS=1
    export GOMP_SPINCOUNT=0        # Idle threads yield the core instead of busy-waiting

    cd $WORKDIR

    # GOMP_CPU_AFFINITY only binds OpenMP threads, not pthreads.
    # taskset -c is the correct tool to pin pthreads to specific cores.
    exec taskset -c 0-2 $BINARY "${LLAMA_ARGS[@]}"

    #nohup taskset -c 0-2 "$BINARY" "${LLAMA_ARGS[@]}" > /dev/null 2>&1 &

Make it executable:
    sudo chmod +x /mnt/data/pi/llama/run_llama.sh

Make the data partion read-only again:
    data-ro.sh
