WindowsDriverInstaller_FFM.java - Win32 API / Native Structure Reference
====================================================================================================

Internal engineering reference. Not a Microsoft document and not a substitute for the Windows SDK.
It exists to help a future maintainer of this class read the FFM (Java Foreign Function & Memory
API) bindings without having to re-derive every struct offset and calling convention from scratch.

This file has two parts:
  PART A - API reference, one entry per native function/struct WindowsDriverInstaller_FFM.java binds.
           Each entry is marked USED (actively called on the current code path) or UNUSED (bound
           and/or documented but not on the current path - kept for reference, per project
           convention, rather than removed). Describes current, correct behavior - no investigation
           narrative.
  PART B - short implementation-history summary (what the hard problems were and how they were
           resolved). This project's driver install/signing pipeline is fully working end-to-end as
           of the entry below; Part B is kept brief and is not an ongoing investigation log.

Where a detail was confirmed against Microsoft's own reference pages, it is marked VERIFIED with a
Source: line. Where something instead has to be reconstructed because Microsoft does not document
it, it is marked RECONSTRUCTED / INFERRED, with brief reasoning.

Some Source: URLs below (Microsoft Learn API reference pages in particular) may prompt for Microsoft
account sign-in when opened directly in a browser, even though the underlying page is public
reference documentation.

No third-party source code is reproduced or excerpted anywhere in this file, and no specific
private/third-party project is named anywhere in this file.

FFM conventions used throughout Part A:

  DW  = ValueLayout.JAVA_INT : used for DWORD, BOOL, LONG, HRESULT, ALG_ID - all 32-bit on Win32,
                               regardless of the process being x64.

  PTR = ValueLayout.ADDRESS  : used for every HANDLE, HWND, HKEY, HCERTSTORE, LP*, or
                               output-by-reference parameter.

All downcalls are bound through the private `_bind(linker, lib, name, fd, options...)` helper, which
does `linker.downcallHandle(lib.find(name).orElseThrow(...), fd, options)` - a plain default-
convention downcall handle for each symbol (Win32 __stdcall, which the FFM Linker's default downcall
convention on Windows already matches), except SetupCopyOEMInfW, which is bound with
`Linker.Option.captureCallState("GetLastError")` (see its entry in Part A, Section F).

DISCLAIMER:
    1. Nothing in this file is copied or paraphrased from Microsoft's text - every description below
       is written from scratch, using the SDK reference pages only to check facts (function/struct
       member existence, order, size, and behavior), not as source text.
    2. Consulted-but-not-copied reference:
           libwdi: A Windows Driver Installation library for USB devices
           https://github.com/pbatard/libwdi/tree/master/libwdi
           Copyright (C) 2010-2023 Pete Batard <pete@akeo.ie> (and some other contributors)
           GNU LGPL version 3 or later
       was read, read-only, to see how another open-source driver installer calls some of these same
       documented Microsoft Win32 APIs (e.g. SetupCopyOEMInfW's OEMSourceMediaType usage). No source
       code from that project is reproduced, adapted, or copied anywhere in this project - every
       binding, struct layout, and comment below was written from scratch against Microsoft's own
       reference pages and this project's own CI results.

A.1 - Process / Elevation Layer (Kernel32.dll, Shell32.dll)
====================================================================================================

This layer exists because two operations elsewhere in the file (certificate creation/trust and
catalog signing/driver staging) need an elevated token, and the only way this FFM backend gets one
is to relaunch its own JVM through ShellExecuteExW with lpVerb="runas" and wait on the resulting
process handle.

----------------------------------------------------------------------------------------------------
CreateFileW - VERIFIED - USED
----------------------------------------------------------------------------------------------------
Source     : https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew
DLL/Header : Kernel32.dll / fileapi.h

Parameters : lpFileName (LPCWSTR), dwDesiredAccess (DWORD), dwShareMode (DWORD),
             lpSecurityAttributes (LPSECURITY_ATTRIBUTES, optional), dwCreationDisposition (DWORD),
             dwFlagsAndAttributes (DWORD), hTemplateFile (HANDLE, optional)
Return     : HANDLE to the opened file, or INVALID_HANDLE_VALUE (-1) on failure.
Purpose    : General-purpose file/device open call.

FFM notes  : `FunctionDescriptor.of(PTR, PTR, DW, DW, PTR, DW, DW, PTR)`. Used once, in
             `_elevatedCreateAndSignCatalog`, to open the INF file with GENERIC_READ /
             FILE_SHARE_READ / OPEN_EXISTING so its bytes can be hashed via
             CryptCATAdminCalcHashFromFileHandle2. The handle is compared against -1L
             (INVALID_HANDLE_VALUE) via `hInfFile.address() == INVALID_HANDLE_VALUE`, and is always
             closed in a `finally` block.

----------------------------------------------------------------------------------------------------
CloseHandle - VERIFIED - USED
----------------------------------------------------------------------------------------------------
Source     : https://learn.microsoft.com/en-us/windows/win32/api/handleapi/nf-handleapi-closehandle
DLL/Header : Kernel32.dll / handleapi.h

Parameters : hObject (HANDLE)
Return     : BOOL
Purpose    : Releases any Win32 kernel handle.

FFM notes  : `FunctionDescriptor.of(DW, PTR)`. Called on both the INF file handle and the elevated
             child process handle (`_shellExecuteElevatedAndWait`), each from a `finally` block.

----------------------------------------------------------------------------------------------------
GetLastError - VERIFIED - USED
----------------------------------------------------------------------------------------------------
Source     : https://learn.microsoft.com/en-us/windows/win32/api/errhandlingapi/nf-errhandlingapi-getlasterror
DLL/Header : Kernel32.dll / errhandlingapi.h

Parameters : none
Return     : DWORD, the calling thread's last-error code.
Purpose    : Standard Win32 extended-error retrieval, read immediately after a failing Win32 call.

FFM notes  : `FunctionDescriptor.of(DW)`. Wrapped by the private `_lastError()` helper (`(int)
             _GetLastError.invoke()`), called from nearly every failure branch in this file. Caveat:
             GetLastError is only meaningful immediately after the failing call, on the same thread,
             before any other Win32 call runs - every call site here follows that rule EXCEPT
             SetupCopyOEMInfW, which instead uses `Linker.Option.captureCallState` (see Section F)
             because a plain separate downcall proved unreliable for that specific, longer-running
             call.

----------------------------------------------------------------------------------------------------
WaitForSingleObject - VERIFIED - USED
----------------------------------------------------------------------------------------------------
Source     : https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-waitforsingleobject
DLL/Header : Kernel32.dll / synchapi.h

Parameters : hHandle (HANDLE), dwMilliseconds (DWORD)
Return     : DWORD - WAIT_OBJECT_0 (0) on signal, WAIT_TIMEOUT (0x102) on timeout, WAIT_FAILED on
             error.
Purpose    : Blocks the calling thread until the given kernel object becomes signaled or times out.

FFM notes  : `FunctionDescriptor.of(DW, PTR, DW)`. Used in `_shellExecuteElevatedAndWait` to wait for
             the elevated child process, timeout = `waitTimeMinutes * 60_000`. Return code compared
             against local constant `WAIT_TIMEOUT = 0x102`; on timeout, calls TerminateProcess and
             reports RETCODE_TIMEOUT.

----------------------------------------------------------------------------------------------------
GetExitCodeProcess - VERIFIED - USED
----------------------------------------------------------------------------------------------------
Source     : https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getexitcodeprocess
DLL/Header : Kernel32.dll / processthreadsapi.h

Parameters : hProcess (HANDLE), lpExitCode (LPDWORD, out)
Return     : BOOL
Purpose    : Reads back a (already-signaled) process's exit code.

FFM notes  : `FunctionDescriptor.of(DW, PTR, PTR)`. Called right after WaitForSingleObject returns
             non-timeout; the exit code buffer is a 4-byte arena allocation read back with
             `exitCodeOut.get(ValueLayout.JAVA_INT, 0)`. This becomes the returned XCom.Pair's first
             element - the elevated child's own `System.exit(exitCode)` value flows back through this
             path.

----------------------------------------------------------------------------------------------------
TerminateProcess - VERIFIED - USED
----------------------------------------------------------------------------------------------------
Source     : https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-terminateprocess
DLL/Header : Kernel32.dll / processthreadsapi.h

Parameters : hProcess (HANDLE), uExitCode (UINT)
Return     : BOOL
Purpose    : Forcibly ends a process; here used only as a timeout backstop.

FFM notes  : `FunctionDescriptor.of(DW, PTR, DW)`. Only reached on the WAIT_TIMEOUT branch, exit code
             1. No follow-up wait after calling this - the code proceeds directly to
             RETCODE_TIMEOUT, so termination is best-effort/fire-and-forget.

----------------------------------------------------------------------------------------------------
LocalFree - VERIFIED - USED
----------------------------------------------------------------------------------------------------
Source     : https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-localfree
DLL/Header : Kernel32.dll / winbase.h

Parameters : hMem (HLOCAL)
Return     : HLOCAL (NULL on success, unlike most BOOL-returning Win32 calls)
Purpose    : Frees memory Crypt32 allocated via the CRYPT_ENCODE_ALLOC_FLAG convention (see
             CryptEncodeObjectEx).

FFM notes  : `FunctionDescriptor.of(PTR, PTR)` - return type is PTR, not DW; the return value is
             discarded at every call site. Called on `ekuEncoded` (Section B) and `spcLinkEnc`
             (Section D), each in a `finally` matching the CryptEncodeObjectEx call that produced it.
             Ownership rule: any buffer CryptEncodeObjectEx returned via its out-pointer with
             CRYPT_ENCODE_ALLOC_FLAG set was allocated by Crypt32's internal allocator and must be
             released with LocalFree only, never by the arena.

----------------------------------------------------------------------------------------------------
ShellExecuteExW - VERIFIED - USED
----------------------------------------------------------------------------------------------------
Source     : https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecuteexw
DLL/Header : Shell32.dll / shellapi.h

Parameters : pExecInfo (SHELLEXECUTEINFOW *, in/out)
Return     : BOOL (TRUE on success; call GetLastError on FALSE)
Purpose    : Launches a file/verb combination through the shell. lpVerb="runas" is what makes UAC
             elevation possible from user code (an elevated COM moniker under the hood, which
             CreateProcess itself cannot invoke).

FFM notes  : `FunctionDescriptor.of(DW, PTR)`. Called once per elevated operation, from
             `_shellExecuteElevatedAndWait`. GetLastError()==1223 (ERROR_CANCELLED) after a FALSE
             return is mapped to RETCODE_UAC_DECLINED (user clicked No on the UAC prompt).

Notes:
    - SEE_MASK_NOCLOSEPROCESS is set, so the returned hProcess handle is the caller's responsibility
      to close (`finally` in `_shellExecuteElevatedAndWait`).
    - lpDirectory is explicitly set to the parent's `user.dir`, since an elevated child's working
      directory is not guaranteed to match the parent's and the launched command line embeds an
      absolute classpath (`_absoluteClassPath()`).
    - nShow: two call sites (createAndTrustProvider/createAndSignCatalog, targeting javaw.exe) use
      SW_HIDE via the no-arg overload; `_shellExecuteElevatedAndWait` also accepts an explicit nShow
      parameter for other callers.

----------------------------------------------------------------------------------------------------
STRUCTURE: SHELLEXECUTEINFOW - VERIFIED - USED
----------------------------------------------------------------------------------------------------
Source    : https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-shellexecuteinfow

Fields    : cbSize(0,DWORD) fMask(4,DWORD) hwnd(8,HWND) lpVerb(16,LPCWSTR) lpFile(24,LPCWSTR)
            lpParameters(32,LPCWSTR) lpDirectory(40,LPCWSTR) nShow(48,int) hInstApp(56,HINSTANCE)
            lpIDList(64,void*) lpClass(72,LPCWSTR) hkeyClass(80,HKEY) dwHotKey(88,DWORD)
            hIcon/hMonitor(96,HANDLE) hProcess(104,HANDLE)
Size      : 112 bytes, 8-byte aligned (x64).
Purpose   : Describes a shell "verb" invocation plus window-state to launch it with, and receives back a
            process handle.

FFM notes : Built by hand in `_shellExecuteElevatedAndWait` via `arena.allocate(SEI_SIZE, 8)` and
            explicit `.set(...)` calls at each SEI_* offset - no reusable StructLayout object, just
            raw offsets. fMask = SEE_MASK_NOCLOSEPROCESS(0x40) | SEE_MASK_NOASYNC(0x100); lpVerb is
            always the literal "runas". All LPCWSTR fields point into the call's own confined Arena
            and are freed automatically when it closes; hProcess is a real kernel handle and IS the
            caller's responsibility (see CloseHandle above).

A.2 - Certificate Store / Self-Signed Certificate Layer (Crypt32.dll)
====================================================================================================

Covers checking for/creating/trusting the self-signed code-signing certificate this tool generates.
Two OS certificate stores matter: the per-machine "Root"/"TrustedPublisher" stores (what actually
makes Windows trust a driver signed with this certificate) and the per-user "My" store (where the
certificate's private-key linkage lives so it can later sign the catalog).

----------------------------------------------------------------------------------------------------
CertOpenStore - VERIFIED - USED
----------------------------------------------------------------------------------------------------
Source     : https://learn.microsoft.com/en-us/windows/win32/api/wincrypt/nf-wincrypt-certopenstore
DLL/Header : Crypt32.dll / wincrypt.h

Parameters : lpszStoreProvider, dwMsgAndCertEncodingType (DWORD), hCryptProv (unused -> 0), dwFlags
             (DWORD), pvPara (provider-specific, here a store name)
Return     : HCERTSTORE, or NULL on failure.
Purpose    : Opens (or implicitly creates) a certificate store of a given provider type/scope/name.

FFM notes  : `FunctionDescriptor.of(PTR, PTR, DW, PTR, DW, PTR)`. lpszStoreProvider is passed as
             `_handleOf(CERT_STORE_PROV_SYSTEM_W)` (=10L) - one of the "predefined, small-integer
             provider" values wincrypt.h expects passed by value in the pointer-typed parameter slot.
             Wrapped by the private `_certStoreOpen(arena, locationFlag, storeName)` helper. Called
             with CERT_SYSTEM_STORE_LOCAL_MACHINE for "Root"/"TrustedPublisher" and
             CERT_SYSTEM_STORE_CURRENT_USER for "My".

----------------------------------------------------------------------------------------------------
CertCloseStore - VERIFIED - USED
----------------------------------------------------------------------------------------------------
Source     : https://learn.microsoft.com/en-us/windows/win32/api/wincrypt/nf-wincrypt-certclosestore
DLL/Header : Crypt32.dll / wincrypt.h

Parameters : hCertStore (HCERTSTORE), dwFlags (DWORD - always 0 here)
Return     : BOOL
Purpose    : Releases a store handle from CertOpenStore.

FFM notes  : `FunctionDescriptor.of(DW, PTR, DW)`. Always flags=0, matched 1:1 with every successful
             CertOpenStore, generally from `finally`.

----------------------------------------------------------------------------------------------------
CertFindCertificateInStore - VERIFIED - USED
----------------------------------------------------------------------------------------------------
Source     : https://learn.microsoft.com/en-us/windows/win32/api/wincrypt/nf-wincrypt-certfindcertificateinstore
DLL/Header : Crypt32.dll / wincrypt.h

Parameters : hCertStore (HCERTSTORE), dwCertEncodingType (DWORD), dwFindFlags (DWORD, always 0),
             dwFindType (DWORD), pvFindPara, pPrevCertContext (optional, always NULL here - "start
             from the beginning")
Return     : PCCERT_CONTEXT matching the search, or NULL.
Purpose    : Certificate-store search primitive; used in single-call form to check whether a
             certificate with a given subject substring already exists.

FFM notes  : `FunctionDescriptor.of(PTR, PTR, DW, DW, DW, PTR, PTR)`. dwFindType is always
             CERT_FIND_SUBJECT_STR_W = (8 << 16) | 7. Used in `isProviderAlreadyTrusted` (search by
             provider name across "Root"/"TrustedPublisher") and `_elevatedCreateAndSignCatalog`
             (locate the signing cert in CurrentUser\My before calling `_signCatalog`).

Ownership  : every non-NULL PCCERT_CONTEXT returned MUST be released with
             CertFreeCertificateContext exactly once - done consistently, either immediately
             (isProviderAlreadyTrusted) or via `finally` around `_signCatalog`.

CertFreeCertificateContext - VERIFIED - USED

DLL/Header : Crypt32.dll / wincrypt.h

Parameters : pCertContext (PCCERT_CONTEXT)
Return     : BOOL
Purpose    : Decrements the refcount of / releases a certificate context.

FFM notes  : `FunctionDescriptor.of(DW, PTR)`. Also called on the certificate this class itself

CertStrToNameW - VERIFIED - USED
----------------------------------------------------------------------------------------------------
Source     : https://learn.microsoft.com/en-us/windows/win32/api/wincrypt/nf-wincrypt-certstrtonamew
DLL/Header : Crypt32.dll / wincrypt.h

Parameters : dwCertEncodingType (DWORD), pszX500 (LPCWSTR), dwStrType (DWORD), pvReserved (NULL),
             pbEncoded (BYTE*, out, may be NULL to query size), pcbEncoded (DWORD*, in/out),
             ppszError (LPCWSTR*, optional out)
Return     : BOOL
Purpose    : Parses an X.500 distinguished-name string into DER-encoded form, the format
             CertCreateSelfSignCertificate's subject parameter requires.

FFM notes  : `FunctionDescriptor.of(DW, DW, PTR, DW, PTR, PTR, PTR, PTR)`. Called twice in
             `_elevatedCreateAndTrustProvider` (standard Win32 size-then-fill pattern): first with
             pbEncoded=NULL to learn the size, then again with an allocated buffer of that size.
             dwStrType = CERT_X500_NAME_STR(3); dwCertEncodingType = X509_ASN_ENCODING(1). ppszError
             is always NULL - this code only checks GetLastError, not the detailed diagnostic.

----------------------------------------------------------------------------------------------------
CertCreateSelfSignCertificate - VERIFIED - USED
----------------------------------------------------------------------------------------------------
Source     : https://learn.microsoft.com/en-us/windows/win32/api/wincrypt/nf-wincrypt-certcreateselfsigncertificate
DLL/Header : Crypt32.dll / wincrypt.h

Parameters : hCryptProvOrNCryptKey (optional), pSubjectIssuerBlob (PCERT_NAME_BLOB), dwFlags (DWORD),
             pKeyProvInfo (PCRYPT_KEY_PROV_INFO, optional), pSignatureAlgorithm
             (PCRYPT_ALGORITHM_IDENTIFIER, optional), pStartTime/pEndTime (PSYSTEMTIME, optional),
             pExtensions (PCERT_EXTENSIONS, optional)
Return     : PCCERT_CONTEXT for the newly built certificate, or NULL.
Purpose    : Builds an in-memory, self-signed X.509 certificate - no CA or network round-trip needed.

FFM notes  : `FunctionDescriptor.of(PTR, PTR, PTR, DW, PTR, PTR, PTR, PTR, PTR)`. Called with:
             hCryptProvOrNCryptKey = the legacy CAPI1 key handle from Section C; pSubjectIssuerBlob =
             the CertStrToNameW-encoded "CN=<providerName>" blob; dwFlags = 0 (certificate IS signed
             and carries a CERT_KEY_PROV_INFO_PROP_ID pointing back at the key container);
             pKeyProvInfo = the hand-built CRYPT_KEY_PROV_INFO (below); pSignatureAlgorithm = an
             explicit SHA256RSA OID; start/end time = NULL, NULL (defaults to now through now + 1
             year); pExtensions = the Enhanced Key Usage extension array.

Notes: If pSignatureAlgorithm were NULL, Microsoft documents the default as SHA1RSA - this class
    always supplies SHA256RSA explicitly, since every other hash in this file (SIP digest,
    SIGNER_SIGNATURE_INFO.algidHash) is pinned to SHA-256. A leap-day edge case in the
    auto-computed +1-year pEndTime is documented by Microsoft and not specially handled here.

CertAddCertificateContextToStore - VERIFIED - USED
----------------------------------------------------------------------------------------------------
Source     : https://learn.microsoft.com/en-us/windows/win32/api/wincrypt/nf-wincrypt-certaddcertificatecontexttostore
DLL/Header : Crypt32.dll / wincrypt.h

Parameters : hCertStore (HCERTSTORE), pCertContext (PCCERT_CONTEXT), dwAddDisposition (DWORD),
             ppStoreContext (optional out, always NULL here)
Return     : BOOL
Purpose    : Copies a certificate context into a store, optionally replacing an existing entry with
             the same identity.

FFM notes  : `FunctionDescriptor.of(DW, PTR, PTR, DW, PTR)`. dwAddDisposition is always
             CERT_STORE_ADD_REPLACE_EXISTING(3), so re-running the trust step is idempotent. Called
             three times per successful trust operation: CurrentUser\My (so the private-key-linked
             certificate is discoverable there later), LocalMachine\Root, and
             LocalMachine\TrustedPublisher (Root establishes the trust anchor; TrustedPublisher marks
             it as an explicitly trusted publisher).

CertGetCertificateContextProperty - VERIFIED - USED
----------------------------------------------------------------------------------------------------
Source     : https://learn.microsoft.com/en-us/windows/win32/api/wincrypt/nf-wincrypt-certgetcertificatecontextproperty
DLL/Header : Crypt32.dll / wincrypt.h

Parameters : pCertContext (PCCERT_CONTEXT), dwPropId (DWORD), pvData (out, NULL to query size),
             pcbData (DWORD*, in/out)
Return     : BOOL
Purpose    : Reads a named property off a certificate context.

FFM notes  : `FunctionDescriptor.of(DW, PTR, DW, PTR, PTR)`. Called in `_destroyPrivateKey` to read a
             certificate's CRYPT_KEY_PROV_INFO property (size-then-fill pattern: dwPropId =
             CERT_KEY_PROV_INFO_PROP_ID(2)), so the legacy CAPI1 key container it names can be
             deleted via CryptAcquireContextW(CRYPT_DELETEKEYSET). A certificate with no such
             property (e.g. the public-only copies installed into LocalMachine\Root/
             \TrustedPublisher) returns 0 on the first call, treated as "nothing to do".

CertDeleteCertificateFromStore - VERIFIED - USED
----------------------------------------------------------------------------------------------------
Source     : https://learn.microsoft.com/en-us/windows/win32/api/wincrypt/nf-wincrypt-certdeletecertificatefromstore
DLL/Header : Crypt32.dll / wincrypt.h

Parameters : pCertContext (PCCERT_CONTEXT)
Return     : BOOL
Purpose    : Removes a certificate from the store it was found in. Always frees the passed context
             regardless of whether deletion succeeds - the caller must not also call
             CertFreeCertificateContext on it.

FFM notes  : `FunctionDescriptor.of(DW, PTR)`. Called in a loop by `_deleteExistingCerts`
             (CurrentUser\My, LocalMachine\Root, LocalMachine\TrustedPublisher) to remove every
             pre-existing certificate matching the provider name before a new one is created. Each
             loop iteration re-queries CertFindCertificateInStore from scratch (pPrevCertContext=NULL)
             since deleting a context invalidates any enumeration position.

CryptEncodeObjectEx - VERIFIED - USED
----------------------------------------------------------------------------------------------------
Source     : https://learn.microsoft.com/en-us/windows/win32/api/wincrypt/nf-wincrypt-cryptencodeobjectex
DLL/Header : Crypt32.dll / wincrypt.h

Parameters : dwCertEncodingType (DWORD), lpszStructType (LPCSTR, may be a small integer cast to
             LPCSTR for predefined types), pvStructInfo (void*), dwFlags (DWORD), pvEncodePara
             (always NULL here), pvEncoded (out - LocalAlloc'd buffer with CRYPT_ENCODE_ALLOC_FLAG),
             pcbEncoded (DWORD*, in/out)
Return     : BOOL
Purpose    : General "encode this in-memory struct into DER/ASN.1" primitive, reused for two payloads.

FFM notes  : `FunctionDescriptor.of(DW, DW, PTR, PTR, DW, PTR, PTR, PTR)`. Always called with dwFlags
             = CRYPT_ENCODE_ALLOC_FLAG(0x8000) - Crypt32 allocates the output buffer via LocalAlloc
             and the caller must free it with LocalFree (done at both call sites). Two uses: (1)
             lpszStructType = `_handleOf(X509_ENHANCED_KEY_USAGE)` (36) with a CERT_ENHKEY_USAGE
             struct, to encode the "code signing" EKU extension; (2) lpszStructType = OID string
             "1.3.6.1.4.1.311.2.1.25" (SPC_CAB_DATA_OBJID, via `_astr`) with an SPC_LINK struct, to
             encode the catalog member's SIP-indirect "file link" payload (Section D).

A.3 - Private Key Provisioning Layer (Advapi32.dll)
====================================================================================================

A.6 - Driver Staging Layer (Setupapi.dll, Cfgmgr32.dll)
====================================================================================================

Stages the INF into Windows without requiring a physically-present device. installDriver()
dispatches to the elevated child exactly like createAndTrustProvider/createAndSignCatalog (via
`_runElevatedSelf("install", ...)`); the elevated child (`_elevatedInstallDriver`) calls
CM_WaitNoPendingInstallEvents as a guard, then SetupSetNonInteractiveMode(TRUE), then
SetupCopyOEMInfW to stage the INF. None of these functions involve COM. An earlier revision instead
shelled out to pnputil.exe /add-driver (matching WindowsDriverInstaller_PS1's approach), but that
reliably hung; the pnputil.exe-based code is kept in `_elevatedInstallDriver`, commented out rather
than deleted, in case it needs to be swapped back in (see Part B).

SetupCopyOEMInfW - VERIFIED - USED
----------------------------------------------------------------------------------------------------
Source     : https://learn.microsoft.com/en-us/windows/win32/api/setupapi/nf-setupapi-setupcopyoeminfw
DLL/Header : Setupapi.dll / setupapi.h

Parameters : SourceInfFileName (PCWSTR), OEMSourceMediaLocation (PCWSTR, optional),

====================================================================================================
A.7 - Miscellaneous Notes for Future Maintainers
====================================================================================================

FFM string-building helpers (`_wstr`, `_astr`):
    `_wstr` produces a NUL-terminated UTF-16LE buffer, 2-byte aligned - the correct native
    representation for every LPCWSTR/LPWSTR parameter in this file. `_astr` produces a NUL-terminated
    single-byte buffer, 1-byte aligned, used only where the real Win32 prototype is genuinely
    ANSI/8-bit (OID strings passed as LPSTR - Crypt32's OID parameters are narrow strings even in "W"
    function variants, since OIDs are ASCII by definition).

Arena discipline: every native call site uses either the process-lifetime shared arena `_arena` (only
    for resolved DLL/symbol lookups at class-init time - never per-call data) or a
    `try (Arena arena = Arena.ofConfined()) { ... }` block scoped to one logical operation. Every
    MemorySegment built with `_wstr`/`_astr`/`_blob`/`_guid`/inline `arena.allocate(...)` is
    automatically reclaimed when its enclosing method returns - the only things needing EXPLICIT
    native-side cleanup are handles/contexts the Win32 APIs themselves allocated (kernel HANDLEs,
    HCERTSTORE, PCCERT_CONTEXT, CAPI1 key/provider handles, HCATADMIN, catalog HANDLEs,
    SIGNER_CONTEXT, and the two LocalFree-owned CryptEncodeObjectEx output buffers). This is the
    single most important invariant to preserve when editing this file: a new native call that
    returns a handle/context needs a matching, correctly-ordered release call, almost always in a
    `finally` block, exactly like every existing call site.

Build command: `make jar JDK_VER=8 && make jar JDK_VER=25` from `src/` is enough after editing any
    source file in this backend (or WindowsDriverInstaller_PS1.java); the first `make` may do
    nothing. Java 8 toolchain: /usr/lib/jvm/java-1.8.0-openjdk-1.8.0.161-0.b14.el7_4.x86_64/bin. Java
    25 toolchain: /opt/openjdk-25_linux-x64_bin/jdk-25/bin.

Elevation architecture: `createAndTrustProvider`/`createAndSignCatalog`/`installDriver` (the public
    entry points that need elevation) never touch NCrypt/Crypt32/Wintrust/Mssign32/Setupapi/Cfgmgr32
    APIs directly from the calling (non-elevated) process - they build a command line and call
    `_runElevatedSelf`, which relaunches this same JVM, elevated, with a hidden marker argument
    (`ELEVATED_OP_ARG`) that routes `main()` into the matching `_elevated*` method instead of any
    normal entry point. The elevated child communicates its result back to the waiting parent
    exclusively through its process exit code (read via GetExitCodeProcess) and a temp log file it
    writes before exiting - there is no shared memory or pipe across the UAC elevation boundary (an
    elevated child runs in a different security context and cannot easily inherit inherited
    standard-handle pipes from a non-elevated parent).

PART B - IMPLEMENTATION HISTORY (compact) - *** RESOLVED ***
====================================================================================================

This backend is fully working end-to-end (certificate creation/trust, catalog signing, driver
staging), confirmed on live Windows CI. The three hard problems along the way, and their resolutions:

Catalog signing (SignerSignEx) returned E_INVALIDARG for a long time. Root cause: three
    SIGNER_* struct fields were wrong simultaneously, each masking the others -
    SIGNER_CERT_STORE_INFO.hCertStore must be NULL under the CHAIN policy this backend uses (not the
    CurrentUser\My handle); SIGNER_SUBJECT_INFO.pdwIndex must point at a real writable DWORD holding
    0 (Microsoft's "must be set to zero" describes the pointed-to value, not the pointer itself); and
    SIGNER_SIGNATURE_INFO.psAuthenticated needed SPC_SP_OPUS_INFO/SPC_STATEMENT_TYPE attributes
    populated. Fixed with all three corrected together (Part A, Section A.5).

The signed .cat file was 0 bytes on disk despite every CryptCATOpen/CryptCATPutMemberInfo/
    CryptCATPutAttrInfo/CryptCATClose call reporting success. CryptCATClose alone does not flush
    content - CryptCATPersistStore must be called first (Part A, Section A.4).

installDriver() (staging the INF via SetupCopyOEMInfW) failed with GetLastError()=0xE000024B
    (SPAPI_E_FILE_HASH_NOT_IN_CATALOG), even though the catalog's hash was confirmed present in the
    catalog database and the .cat file was confirmed Authenticode-trusted. Root cause, found by
    matching a known-working catalog shape field-by-field: CryptCATOpen's dwPublicVersion must be 0
    (not CRYPTCAT_VERSION_2/0x200), matching dwCertVersion=0 in CryptCATPutMemberInfo, with catalog
    members keyed to a fixed INF-type subject GUID (INF_SUBJECT_TYPE_PARTS, not one derived from
    CryptSIPRetrieveSubjectGuid/DRIVER_ACTION_VERIFY) and SHA1-only members (Part A, Section A.4). An
    earlier attempt to sidestep this by shelling out to pnputil.exe /add-driver (matching
    WindowsDriverInstaller_PS1) reliably hung instead; that code is kept commented out in
    `_elevatedInstallDriver`, not deleted, in case it is useful again, but SetupCopyOEMInfW with the
    parameter combination above is the current, working, active path (Part A, Section A.6).

Two smaller fixes along the way: SetupCopyOEMInfW can raise an interactive dialog that hangs forever
    in a headless elevated child with no message pump - fixed by calling
    SetupSetNonInteractiveMode(TRUE) immediately before it. And a plain, separate GetLastError()
    downcall after SetupCopyOEMInfW proved unreliable (the JVM can run its own Win32 calls on the same
    OS thread in the gap, e.g. a GC/safepoint poll, overwriting the thread-local error value) - fixed
    by binding SetupCopyOEMInfW with `Linker.Option.captureCallState("GetLastError")` instead.
