FILE:    JDrawChart.java
LINE:    final double yScale = ( (double) ah - Padding2 - XLabelPadding ) / (ds.maxValue - ds.minValue);
ISSUE:   Potential division by zero / NaN propagation.  After the alignment
         block (lines 235-246), ds.maxValue and ds.minValue are set from
         _align().  When _align() is called with 0.0 it returns 1.0, so for an
         all-zero dataset ds.maxValue == 1.0 and ds.minValue == 0.0 -- that is
         fine.  However the mixed-sign branch (else, lines 243-246) assigns:
             ds.maxValue = (ds.maxValue >= 0) ? aligned : -aligned;
             ds.minValue = (ds.minValue >= 0) ? aligned : -aligned;
         When ds.maxValue > 0 and ds.minValue < 0, both fields receive the
         same absolute value (aligned), so ds.maxValue == aligned and
         ds.minValue == -aligned, making ds.maxValue - ds.minValue == 2*aligned
         which is correct.  But when both are exactly 0.0 after alignment
         (edge case if somehow aligned == 0), the denominator would be zero.
         The _align() function guards n <= 0 by returning 1.0, so this is
         unlikely in practice, but mathematically not fully ruled out.
SUGGEST: Add a defensive guard after the alignment block:
             if(ds.maxValue == ds.minValue) return;
         This would silently skip drawing when there is no vertical range, which
         is the safest observable behavior.
